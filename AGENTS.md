# AGENTS.md

Инструкции для ИИ-агентов, которые работают с этим репозиторием.

## Что это

Плагин Claude Code `onec-dump`: скиллы и скрипты для выгрузки конфигурации 1С в формате Конфигуратора. Подробности в [README.md](README.md) и [docs/ROADMAP.md](docs/ROADMAP.md).

## Правила разработки

- Язык скриптов: Python 3.10+, только стандартная библиотека. Зависимости не добавлять.
- Скрипты лежат в `skills/onec-configurator/scripts/`, тесты: `tests/` (индекс) и `skills/onec-configurator/tests/` (остальные). Перед коммитом проходят оба набора.
- Выгрузки 1С — UTF-8 с BOM, часто с CRLF. Читать с `utf-8-sig`, при записи сохранять BOM и переводы строк исходного файла.
- Имена в выгрузке кириллические. Пути всегда в кавычках, кодировку консоли не предполагать (`PYTHONUTF8=1`).
- Скрипты читают файлы потоково и печатают компактный результат. Лимит вывода по умолчанию 150 строк, с пагинацией.
- Скрипты, которые меняют файлы, обязаны: делать резервную копию, поддерживать режим `--dry-run`, проверять версию формата выгрузки и не трогать `ConfigDumpInfo.xml`.
- `Form.bin` обычных форм никогда не сжимать и не править как текст.
- Номер версии формата записывать по версии платформы выгрузки: 8.3.27 → 2.20, 8.5.1 → 2.21. Не подставлять старую версию по умолчанию.

## Правила для скиллов

- `name`: kebab-case, префикс `onec-`, до 64 символов.
- `description`: что делает и когда использовать, ключевой случай в начале, до 400 символов (лимит листинга Claude Code — 1536).
- Тело `SKILL.md` до 400 строк. Всё длинное уходит в `references/` с указанием, когда его читать.
- Скилл, который меняет файлы, не должен заранее разрешать неограниченный `Bash`. Разрешать только вызов своих скриптов.

## Данные и лицензии

- Тексты стандартов разработки 1С лежат в `skills/onec-configurator/standards/` (решение владельца проекта: офлайн-копия входит в публичный репозиторий). Каждый файл несёт указание источника и правообладателя (© фирма «1С»), в `skills/onec-configurator/standards/README.md` описано, что тексты можно убрать по требованию правообладателя. Обновлять только скриптом `skills/onec-configurator/scripts/sync_standards.py`, вручную не редактировать. Собственные пояснения и сопоставление с диагностиками хранить отдельно от дословных текстов.
- Код и тексты из чужих проектов копировать только при совместимой лицензии (MIT, Apache-2.0, CC0) и с записью в NOTICE.md. AGPL и проекты без лицензии не копировать.
- Реальные выгрузки заказчика в репозиторий не добавлять. Тестовые данные: публичная выгрузка БСП и фикстуры из MIT-проектов, получаемые скриптом.

## Проверка

- Тесты запускаются в GitHub Actions на Windows и Linux (`.github/workflows/tests.yml`); после push проверить результат.
- Перед коммитом: запуск тестов на фикстурах. Длина описаний скиллов, заголовки стандартов и согласованность версий проверяются тестом `tests/test_repo_rules.py`.
- Правки XML проверяются структурно. Загрузку в информационную базу (`/LoadConfigFromFiles`) агент проверить не может, это шаг для человека на машине с платформой.
