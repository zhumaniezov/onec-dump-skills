# onec_gen.py sheet draft — JSON-описание существующего макета

> Справка к `onec_gen.py sheet draft`. Основано на документации открытого проекта (лицензия MIT,
> NOTICE.md). Файл создаётся `scripts/sync_engine.py`, вручную не править.


Принимает Template.xml табличного документа 1С и генерирует компактное JSON-определение (DSL). Обратная операция к `sheet build`.

## Использование

```
`sheet draft` <TemplatePath> [OutputPath]
```

## Параметры

| Параметр     | Обязательный | Описание                                |
|--------------|:------------:|-----------------------------------------|
| TemplatePath | да           | Путь к Template.xml                     |
| OutputPath   | нет          | Путь для JSON (если не указан — stdout) |

## Команда

```text
python "${CLAUDE_SKILL_DIR}/scripts/onec_gen.py" sheet draft -TemplatePath "<путь>/Template.xml" [-OutputPath "<путь>.json"]
```

## Рабочий процесс

Декомпиляция существующего макета для анализа или доработки:

1. Вызвать `sheet draft` для получения JSON из Template.xml
2. Проанализировать или изменить JSON (добавить области, поменять стили)
3. Вызвать `sheet build` для генерации нового Template.xml
4. Вызвать `sheet check` для проверки

Формат JSON на выходе — тот же DSL, что принимает `sheet build`; его описание живёт в навыке `sheet build`.

## Ключи, которых нет в описании DSL

В разобранном макете попадаются ключи, которых нет в инструкции `sheet build`: например,
у `rowStyle` — модификатор `apply`, у ячейки-поля ввода — `controlType: "none"`. Они несут
состояние исходного файла, которое иначе не выразить. Писать их самому не нужно; удалять
из разобранного JSON — тоже: компилятор принимает их обратно как есть, а без них макет
изменится.

## Что нужно знать о пересборке

Правка через DSL — это полная перегенерация макета, а не точечное изменение XML. Поэтому
diff после цикла «декомпиляция → компиляция» обычно шире фактической доработки, даже когда
содержание сохранено целиком.

Побайтового совпадения с исходником ждать не всегда стоит. В макетах, которые долго правили
в Конфигураторе, остаются следы прежних состояний: например, формат ячейки несёт ширину
колонки, которая с тех пор изменилась. Из итогового документа такие значения не выводятся,
и в пересобранный файл они не возвращаются.

Не переживают цикл вовсе (в JSON не попадают, в XML не возвращаются):

- объединения, не привязанные к ячейке — по всей высоте или ширине документа;
- настройки диаграмм (`Chart`, `GanttChart`) — сам рисунок сохраняется, его содержимое нет;
- область печати.

Если задача — сохранить чужой макет как есть и поправить в нём малое, сверяйте результат
`sheet info` или diff-ом: перечисленное выше нужно вернуть руками.
