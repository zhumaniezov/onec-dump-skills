# XML выгрузки Конфигуратора

## Границы формата

Работать с результатом «Выгрузить конфигурацию в файлы» / `/DumpConfigToFiles`.
Бинарные CF/CFE/EPF/ERF требуют платформы или отдельно проверенного инструмента.
EDT `.mdo`, `.form`, `.dcs` не смешивать с выгрузкой Конфигуратора. При обнаружении
таких файлов определить корень, не конвертировать проект молча.

| Путь/имя | Назначение |
|---|---|
| `Configuration.xml` | Свойства и состав конфигурации/расширения |
| `ConfigDumpInfo.xml` | Служебные сведения и версии объектов выгрузки |
| `Catalogs/Имя.xml`, `Documents/Имя.xml` | Описание объекта |
| `Имя/Ext/ObjectModule.bsl`, `ManagerModule.bsl` | Модули объекта и менеджера |
| `CommonModules/Имя/Ext/Module.bsl` | Общий модуль |
| `Forms/Имя.xml`, `Forms/Имя/Ext/Form.xml` | Метаданные и содержимое формы |
| `Forms/Имя/Ext/Form/Module.bsl` | Модуль формы в распространённом layout |
| `Templates/Имя/Ext/Template.xml` | XML содержимое макета, например СКД |
| `Roles/Имя/Ext/Rights.xml` | Права |
| `Ext/Predefined.xml` | Предопределённые данные |

Это ориентиры, пути проверять поиском. `version` корневого XML относится
к формату сериализации и не заменяет версию платформы/совместимость.

## Инварианты

Сохранить UUID объектов и вложенных метаданных, внутренние TypeId/ValueId и
GeneratedType, идентификаторы/ссылки элементов форм и предопределённых данных.
Повторение UUID в ссылке или заимствовании не равно дублированию нового объекта.

Сохранить пространства имён, включая префиксы в строковых QName (`xsi:type`,
описания типов). Парсер XML не доказывает семантическую корректность XDTO.
Не сортировать дочерние узлы, права и свойства, не удалять пустые элементы
«для красоты». Не переносить узлы из другой версии без эталона и проверки.

## Точечная правка

1. Прочитать узел с Properties, ChildObjects и описаниями типов.
2. Найти аналог того же вида и формата в текущей конфигурации.
3. Установить тип, длину/точность, доступность, связи и необходимые права.
4. Менять локально. Перед структурным редактором проверить, как он сохраняет
   неизменённый файл: не переписывать весь XML с новым форматированием.
5. Проверить well-formed XML, при наличии точной XSD — соответствие схеме.
6. Просмотреть diff; изменения UUID/типов объяснить отдельно.
7. Загрузить в тестовую ИБ, проверить поведение и повторную выгрузку.

Текстовая замена применима к однозначному фрагменту с проверкой числа совпадений.
Регулярное выражение по всему проекту не понимает модель XML.

## Создание, удаление, переименование

Новый объект включает регистрацию в ChildObjects владельца, внутренние типы,
вложенные объекты, формы/макеты, подсистемы, команды, роли и ссылки. Предпочесть
эталонный каркас произвольной генерации. При копировании аналога разделить
UUID нового объекта и ссылки на существующие сущности. Не заменять все UUID.
Сторонний генератор применять после проверки его поддерживаемых типов/версий.

При переименовании сохранять идентичность, проверять строковые обращения,
запросы, типы, роли, XDTO и расширения. До удаления проверить входящие ссылки
и последствия для данных. Не удалять `ConfigDumpInfo.xml` ради чистого diff,
не выдумывать его хеши/версии; обслуживать штатными операциями данной платформы.

Файловая проверка доказывает читаемость XML. Работоспособность подтверждают
загрузка, проверка платформой, обновление тестовой БД и выполнение сценария.
