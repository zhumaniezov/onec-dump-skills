# Контекст проекта и навигация

> Для карточек объектов и «где используется» на больших конфигурациях основной инструмент — `onec_index.py` (см. navigation.md): он кэширует индекс и учитывает типы, роли, подсистемы, формы. Команды `index`/`references` ниже — запасной лексический путь, когда индекс не построен.

Сначала прочитать CLAUDE.md/rules, статус Git и профиль проекта. Не устанавливать
инструменты ради чтения доступных файлов. `project_context.py` использует только
Python 3.10+ stdlib, ничего не пишет в выгрузку и не запускает найденные программы.

## Команды

```text
python "${CLAUDE_SKILL_DIR}/scripts/project_context.py" doctor "<проект>" --profile "<doctor.json>"
python "${CLAUDE_SKILL_DIR}/scripts/project_context.py" index "<src/cf>" --limit 100
python "${CLAUDE_SKILL_DIR}/scripts/project_context.py" api "<src/cf>" --name "ИмяМетода" --exported-only
python "${CLAUDE_SKILL_DIR}/scripts/project_context.py" references "<src>" --symbol "ОбщийМодуль.Метод"
python "${CLAUDE_SKILL_DIR}/scripts/project_context.py" references "<src>" --symbol "Справочник.Товары" --include-text
```

`index` читает XML правильного namespace MDClasses и прямые Properties владельца;
имя вложенного реквизита не становится именем конфигурации. Показывает состав
ChildObjects, UUID, формат, флаги общих модулей. Не строит полный граф ссылок.

`api` выводит определения процедур/функций, исходную сигнатуру, путь/строку,
Экспорт и директивы. Учитывает русский/английский синтаксис, многострочные
параметры, комментарии и строки. `references` ищет лексические употребления;
режим `--include-text` добавляет строки запросов и комментарии.

Это **лексический поиск**, не BSL-парсер: не разрешает типы, динамические вызовы,
условную компиляцию или область видимости. Незакрытая строка может скрыть
остаток файла. Для семантики использовать BSL LS, точечное чтение и платформу.
После поиска читать реализацию и соседний контекст, а не только совпадение.

По умолчанию максимум файла 16 MiB, максимум выдачи 200 записей; доступны
`--max-mib` и `--limit`. При ограничении выдачи проверять total/truncated.
Повреждённые файлы, неподдерживаемая кодировка и пропущенные ссылки дают
`partial` с ненулевым кодом. Файлы со старой кодировкой не перекодировать автоматически.

## Doctor

Профиль: `assets/doctor.example.json`. Поля: schema=1; platform.path,
platform.version; tools.powershell/oscript/java/git. Не хранить пароли или
строки подключения. Относительный путь отсчитывается от файла профиля;
имя исполняемого файла сначала ищется в PATH.

Найти, что установлено (версии платформы, базы из списка 1С, OneScript), — `onec_env.py discover`
(pipeline.md, «Быстрый путь»). Doctor проверяет уже выбранное.

Без профиля платформа остаётся невыбранной: наличие нескольких 1cv8 не позволяет
самовольно выбрать последнюю. `--require platform` делает отсутствие выбранной
платформы ошибкой; аналогично powershell/oscript/java/git. Без обязательных
возможностей doctor может вернуть ok, а platform.available=false — файловая
работа доступна. Это не успешная проверка сборки.

`version_declared` — заявленная версия; `version_verification=not_run` означает,
что программа не запускалась. Для реального build отдельно проверить бинарник
и его справку. Конфигурации выводятся с собственными Version/CompatibilityMode/
format_version: они не доказывают версию установленной платформы.

## Контекст большого проекта

1. Индексировать нужный корень, не всю рабочую станцию.
2. Найти объект и модуль; затем прямые вызовы, подписки и расширения.
3. Для БСП искать экспортный метод в **локальной версии** и проверять сигнатуру.
4. Для UI проследить начальные свойства, обработчики и изменения видимости.
5. Для запроса включить текстовый поиск по именам таблиц, затем проверить пакет.
6. Сохранить краткую карту фактов: объект → файл/строка → причина → проверка.
   Не загружать весь индекс и все references в контекст без необходимости.
