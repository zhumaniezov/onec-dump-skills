# Конфигуратор и командная строка

Дополнение для полного/инкрементального обмена:
[export-contract.md](export-contract.md). Выбор версий и стендов:
[platform-matrix.md](platform-matrix.md).

## Подготовка

Указать абсолютный путь к конкретному `1cv8.exe`, тестовую ИБ, корень XML,
основную конфигурацию или имя расширения, формат и файлы журналов. Не выбирать
«последнюю установленную» версию. Проверять справку запуска установленной
платформы и её руководство администратора: набор ключей меняется.

В примерах ниже пути условные; это шаблоны последовательности, не готовая
универсальная команда. Использовать уже разрешённую тестовую базу. Если она
не определена, подготовить команды без запуска записи.

## Три отдельных шага

1. Загрузить файлы в редактируемую конфигурацию.
2. Проверить конфигурацию и модули.
3. Обновить конфигурацию базы данных и выполнить сценарий.

Не считать эти действия одним и тем же. Git pull не запускает их автоматически.
Для каждой команды сохранять свежий лог, код процесса и результат операции;
не принимать старый файл журнала за результат нового запуска.

## Типовые шаблоны для Windows

Ниже команды запускаются в PowerShell. Значения заполнить по профилю. Для
серверной базы использовать `/S` вместо `/F`; не передавать оба подключения.
Аутентификацию выбирать по стенду, секреты не помещать в историю команд.

```powershell
$OneCExe = 'C:\Program Files\1cv8\<точная-сборка>\bin\1cv8.exe'
$TestBase = 'C:\1C-Test\Project'
$SourceRoot = 'C:\git\Project\src\cf'
$RoundtripRoot = 'C:\1C-Test\roundtrip-new-empty'
$CheckLog = 'C:\1C-Test\logs\check-current.log'
```

Выгрузка для сравнения — только в новый пустой каталог вне изменяемых исходников:

```powershell
& $OneCExe DESIGNER /F $TestBase /DisableStartupDialogs /DumpConfigToFiles $RoundtripRoot /Out 'C:\1C-Test\logs\dump-current.log'
```

Загрузка исходников в выбранную тестовую ИБ — самостоятельная операция записи:

```powershell
& $OneCExe DESIGNER /F $TestBase /DisableStartupDialogs /LoadConfigFromFiles $SourceRoot /Out 'C:\1C-Test\logs\load-current.log'
```

Проверка конфигурации — после успешной загрузки и чтения её свежего лога:

```powershell
& $OneCExe DESIGNER /F $TestBase /DisableStartupDialogs /CheckConfig -ConfigLogIntegrity -IncorrectReferences -ThinClient -Server -ExtendedModulesCheck /Out $CheckLog
```

Обновление конфигурации БД — отдельная операция после проверки и оценки
изменений структуры/данных:

```powershell
& $OneCExe DESIGNER /F $TestBase /DisableStartupDialogs /UpdateDBCfg /Out 'C:\1C-Test\logs\update-current.log'
```

Выбирать операцию по задаче, не запускать все примеры подряд. До выгрузки
убедиться, что RoundtripRoot не совпадает с SourceRoot и не содержит нужных
файлов. До загрузки проверить назначение TestBase и выбранное расширение.
В PowerShell для надёжного ожидания GUI-процесса применять проверенную обёртку
проекта либо `Start-Process -Wait -PassThru` с корректным цитированием аргументов.
Следующая стадия запускается только после завершения и проверки предыдущей.

Для обычного/толстого/веб-клиента выбрать соответствующие флаги `/CheckConfig`
по справке, а не ограничиваться ThinClient. `-Extension <имя>` использовать
только у команд, где он поддерживается, и проверять нужное расширение отдельно.

## Частичная загрузка и служебные сведения

Различать списки объектов для выгрузки и списки файлов для загрузки. Формат,
кодировку, полноту зависимостей и ключ `-listFile` проверить для своей версии.
Не копировать `-partial` как универсальный параметр: он указан в некоторых
новых руководствах, но его доступность и семантику сверять с целевой сборкой.
Не использовать игнорирование неразрешённых ссылок
как способ скрыть неполную конфигурацию.

Инкрементальный режим опирается на служебные сведения выгрузки. После ручных
изменений и миграций проверить актуальность ConfigDumpInfo штатным способом.
Для новой тестовой базы и непонятной частичной загрузки сначала предпочесть
полный воспроизводимый цикл на копии, если размер позволяет.

## Внешние обработки/отчёты

Команды семейства `/LoadExternalDataProcessorOrReportFromFiles` и
`/DumpExternalDataProcessorOrReportToFiles` имеют собственные аргументы:
корневой XML, файл EPF/ERF и каталог выгрузки. Порядок и доступные параметры
проверить в руководстве точной версии перед построением команды.

## Подтверждение результата

Завершённый процесс с кодом 0 ещё проверить по свежему логу и ожидаемому
артефакту/состоянию ИБ. При зависании проверить модальный диалог, блокировку
и процесс; не запускать ещё один загрузчик в ту же ИБ. Отсутствие платформы
зафиксировать как пропуск платформенной проверки, продолжив статическую работу.
