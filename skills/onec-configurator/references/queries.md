# Запросы 1С

## Инструмент: извлечение и проверка запросов

`scripts/onec_query.py` находит запросы в модулях (многострочные строки с `|`),
схемах СКД (`Template.xml`, `<query>`) и динамических списках (`Form.xml`, `<QueryText>`)
и проверяет их. Таблицы и поля сверяются с индексом `onec_index.py` (построить заранее).

```text
python "${CLAUDE_SKILL_DIR}/scripts/onec_query.py" scan "<файл | папка объекта | корень>" [--errors] [--rule R]
python "${CLAUDE_SKILL_DIR}/scripts/onec_query.py" show "<файл>" [--line N]
```

| Правило | Что значит | Как реагировать |
|---|---|---|
| `unknown-table` | объекта нет в конфигурации | опечатка или объект другой библиотеки (например, БТС в модулях «…ВМоделиСервиса») — проверить, выполняется ли код условно |
| `unknown-tabular-section` | у справочника, документа или ПВХ нет такой табличной части | опечатка в источнике `Вид.Объект.ТабличнаяЧасть` — исправить имя |
| `unknown-field` | у таблицы, табличной части или ссылочного поля нет такого поля | исправить имя; при разыменовании составного типа сверить все типы |
| `vt-where` | отбор по **измерению** виртуальной таблицы в `ГДЕ` | перенести в параметры таблицы (#std657); условия на ресурсы в `ГДЕ` допустимы и не отмечаются |
| `query-in-loop` | выполнение запроса в теле `Для`/`Для Каждого` | собрать данные одним запросом (#std436); осознанные места помечают `// @skip-check query-in-loop` |
| `full-join` | `ПОЛНОЕ СОЕДИНЕНИЕ` | переписать без него, если возможно (#std435) |

Текст стандарта из замечания: `onec_std.py show 657 --clause 1` (офлайн).

Границы: анализ лексический. Шаблоны, которые модуль дописывает `СтрЗаменить`, по видимому
тексту не считаются ошибкой; текст, собранный из переменных, проверяется частично.
Поля проверяются у справочников, документов, их табличных частей, перечислений, ПВХ,
регистров сведений (включая срезы) и накопления (включая остатки и обороты). Регистры
бухгалтерии и расчёта, планы счетов, бизнес-процессы, задачи — только наличие объекта; такие
источники `scan` перечисляет строкой «Поля не проверялись …» — в отчёте пользователю сказать, что
их поля не проверены.
Цикл `Пока` (порционное чтение, повторы) правилом `query-in-loop` не отмечается.
Отсутствие замечаний не доказывает корректность запроса: смысл, кратность соединений
и производительность проверять по разделам ниже и на данных.

## Контракт результата

Перед запросом зафиксировать гранулярность строки, ключ, состав полей, период,
организацию/разделение данных, правила отбора, смысл пустых значений и права.
Проверить метаданные: вид регистра, измерения, ресурсы, периодичность, типы
реквизитов и регистраторы. Имена SQL-таблиц СУБД не являются именами таблиц языка 1С.

Параметризовать значения через `&Параметр` и `УстановитьПараметр`. Имя таблицы
параметром значения не подставляется; динамические идентификаторы выбирать из
контролируемого перечня метаданных. Запрос 1С не поддерживает произвольный SQL.

Оформлять ключевые слова заглавными, назначать устойчивые псевдонимы, явно
указывать `КАК`, разбивать запрос на строки. Это #std437. Не использовать `*`
в прикладном контракте, когда состав полей должен быть устойчивым.

## Соединения и кратность

Для каждого соединения установить кардинальность: 1:1, 1:N или N:M. Сверять
число строк и суммы до/после. Если соединение размножает строки, исправить
ключ/источник/предварительную агрегацию; `РАЗЛИЧНЫЕ` не доказывает исправление.
Условие на правую таблицу в `ГДЕ` может убрать строки левого соединения с Null.
Различать условие соединения, фильтр источника и фильтр готового результата.

`ЕСТЬNULL` обрабатывает Null, но не любую пустую ссылку/строку. Составные типы
анализировать по метаданным; при необходимости ограничивать `ССЫЛКА`/`ВЫРАЗИТЬ`
с пониманием потерь строк и генерируемых соединений. Не преобразовывать ссылку
в представление для сопоставления данных.

## Виртуальные таблицы

Отборы в параметрах виртуальной таблицы часто сокращают работу. Переносить их
только после доказательства сохранения смысла. Особенно важен `СрезПоследних`:

- внешний `ГДЕ Источник = &Источник` проверяет источник уже выбранной последней записи;
- условие внутри `СрезПоследних(, Источник = &Источник)` выбирает последнюю
  запись среди удовлетворяющих условию.

При новой записи другого источника эти результаты различаются, если Источник
является реквизитом/ресурсом и обе записи имеют один набор измерений. Если
Источник — измерение, это разные ключи среза: данный контрпример неприменим.
Пример для реквизита: вчера Источник=A, сегодня Источник=B. На сегодня внешний
отбор A не возвращает строку, внутренний может вернуть вчерашнюю A.
Не применять правило «все отборы внутрь» без такого разбора.

Для остатков/оборотов сверить вид регистра, имена виртуальных таблиц, поля,
периодичность, дополнение периодов и поддерживаемые параметры конкретной версии.
Условия по ресурсам и измерениям имеют разный смысл. Проверять границу включения
периода, особенно при остатках на момент документа.

## Даты и пакеты

Уточнить: календарные дни, точный момент, начало/конец периода, часовой пояс
сервиса. Не прибавлять произвольную секунду без контракта. Для простого отбора
по дате часто удобно `[Начало, СледующееНачало)`, но виртуальные таблицы имеют
собственную семантику границ — сверить справку.

Временные таблицы использовать для повторного применения, уменьшения объёма и
упрощения связей. Индексировать по фактическим соединениям/отборам после замера.
Следить за временем жизни МенеджераВременныхТаблиц и доступностью результата
пакета. Новые возможности временных таблиц не переносить на старую платформу
без проверки. Создание временной таблицы в каждом проходе не устраняет N+1.

## Права и проверка

`РАЗРЕШЕННЫЕ` — сознательное решение о неполной выборке, не универсальное лечение
ошибки доступа. Для финансовых/контрольных итогов неполнота может быть дефектом.
Режим привилегий не включать ради скорости или скрытия проблемы прав.

Проверить пустую выборку, одну строку, дубли, Null, пустые ссылки, начало/конец
периода, несколько организаций, ограниченные права. Для оптимизации сравнить
ключи, количество, суммы и время на одном снимке данных. Сортировка результата
должна быть явной там, где от неё зависит поведение.

Статический разбор строки не подтверждает существование таблиц и бизнес-смысл.
Исполнить запрос на тестовой базе или явно указать отсутствие этого шага.
