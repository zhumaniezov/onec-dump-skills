# Регистры, запись и исправление данных

## Прежде чем писать код

Установить вид регистра, независимость/подчинение регистратору, периодичность,
измерения, ресурсы, реквизиты, регистраторы, режим блокировок и обработчики.
Выгрузка конфигурации содержит метаданные/код, не текущие записи регистра.

Задать инварианты: какие строки допускается менять, что должно сохраниться,
ожидаемое число строк и суммы, поведение повторного запуска, коллизий и отказа.
Для изменения измерения описать старый и новый ключ. Период и его точность
являются частью идентичности периодического регистра по правилам платформы.

## Независимый регистр сведений

Выбрать менеджер записи для адресной операции или набор для доказанной области
замещения. Для менеджера сначала прочитать запись по полному старому ключу и
проверить результат; изменение ключа и режим записи сверить со справкой целевой
версии. Не создавать только новую запись, забыв старую.

Для набора Отбор определяет область чтения и замещения, а не просто удобство
выборки. Набор только из изменённых строк при широком отборе и замещении может
удалить остальные. Пустой отбор может охватить весь регистр. Добавление без
замещения не является обновлением по ключу и может оставить старые записи.

При изменении измерения отбор по его старому значению может не разрешать запись
нового значения. Выбрать корректную область или адресный алгоритм; не снимать
отбор и не записывать частичный набор поверх всего регистра.

## Регистр, подчинённый регистратору

Прочитать полный набор нужного регистратора, сохранить все необходимые строки,
изменить целевые значения, записать набор по правилам платформы. Проверить
НомерСтроки, Активность, Период и вид движения там, где применимо. Прямую запись
не выдавать за перепроведение: она не выполняет всю логику документа.
Проверить модуль набора, подписки и обмены — запись может иметь побочные эффекты.

## Без перепроведения документов

Для поручения «заполнить измерение, документы не перепроводить»:

1. Зафиксировать тестовую ИБ и снимок затрагиваемой области со всеми полями.
2. Построить план старых/новых ключей и значений; неоднозначное соответствие
   вывести отдельно. Не искать ссылку по одному представлению без уникальности.
3. Найти коллизии между изменяемыми и неизменяемыми строками. Не объединять
   ресурсы и не перетирать конфликтующие записи без бизнес-правила.
4. Организовать короткую транзакцию и блокировки/исключение конкурентной записи
   до чтения значений для изменения. Транзакция сама по себе не решает lost update.
5. Внутри операции проверить актуальность старых значений, выполнить запись
   через подходящий API регистра. Документы не записывать/проводить.
6. До фиксации сверить число строк, ключи, неизменяемые поля и ожидаемые итоги;
   при расхождении откатить. Повторный запуск должен иметь определённый результат.
7. Проверить последствия будущего перепроведения: оно может восстановить
   прежнее значение; при необходимости отдельно исправить алгоритм заполнения.

При 40 строках приемлема простая адресная обработка. Для миллионов — партии,
контрольные точки, возобновление, детерминированный ключ и измеренный размер
транзакции. Не начинать с усложнения, которого не требует объём.

## Документы и проведение

Различать объект документа, движения, запись набора и проведение. Проверить
набор регистров, отбор по регистратору, необходимость чтения старых движений,
порядок блокировок и отказ. При перепроведении не оставлять старые движения
других веток алгоритма. При записи в цикле оценить транзакционный объём.

Сетевые запросы и ожидание пользователя не держать внутри транзакции БД.
При повторе после взаимоблокировки повторять всю логическую операцию по
обоснованной политике, а не последний вызов Записать на устаревших данных.

## Ограничения версии

Не использовать современные режимы записи/merge на старой платформе только
потому, что они существуют в актуальной документации. Проверить целевую сборку
и совместимость в `api-help.md`. Прямые SQL UPDATE к таблицам 1С не являются
штатным способом исправления данных этого комплекта.
