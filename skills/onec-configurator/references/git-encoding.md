# Git, кодировки и повторная выгрузка

## Перед правкой

```bash
git status --short
git -c core.quotepath=false ls-files --eol -- 'src/cf/путь/Module.bsl'
git check-attr text eol filter working-tree-encoding diff -- 'src/cf/путь/Module.bsl'
git config --show-origin --get-regexp 'core\.(autocrlf|eol|safecrlf)'
```

`i/` описывает индекс, `w/` рабочее дерево; `mixed` означает смешанные переводы
строк в соответствующем представлении. Это не доказательство изменения кода.
Проверить также BOM, кодировку, табы/пробелы и действительные строки diff.

## Политика окончаний строк

Сохранять действующую `.gitattributes`. Не менять глобальный Git config для
исправления одного проекта. Для нового проекта выбрать одну обоснованную политику:

| Цель | Пример правила | Следствие |
|---|---|---|
| Нормализованный текст BSL | `*.bsl text eol=crlf` | LF в индексе, CRLF при checkout |
| Байтовое сохранение XML | `*.xml -text diff` | Нет нормализации EOL, текстовый diff принудительно |
| Байтовое сохранение BSL | `*.bsl -text diff` | Переносы хранятся как есть |

`eol` и `text` выбирать согласованно. Не назначать `text` бинарным CF/CFE/EPF/ERF,
MXL и изображениям. Эти примеры — варианты, не комплект для слепой вставки.

## Массовый diff

1. Сохранить рабочие изменения и исходную выгрузку, не делать `reset --hard`.
2. Сверить точную сборку платформы, формат выгрузки, исходную конфигурацию и
   расширения. Одинаковая совместимость не означает одинаковую сериализацию.
3. Сравнить обычный diff и `git diff --ignore-cr-at-eol`. Игнорирование пробелов
   использовать для диагностики: пробел внутри строки/запроса может быть значим.
4. Отделить форматирование от смысловой правки, проверить реальные байты.
5. При согласованной нормализации применять `git add --renormalize` к точным
   путям и просмотреть staged diff. Команда меняет индекс, не только отчёт.
6. Сравнить XML по идентичности, составу и ссылкам. Перестановки и изменения
   UUID/ChildObjects не списывать на EOL.
7. Повторить загрузку/выгрузку на тестовой копии той же сборкой; объяснить
   остаточные различия до коммита.

`git diff -w` и массовая XML-сериализация не лечат причину. Нормализация EOL
не исправляет табы/пробелы, неправильно декодированную кириллицу или UUID.

## Windows и Unicode

PowerShell 5.1, PowerShell 7, Python и перенаправление stdout могут записывать
разные кодировки. Указывать кодировку явно, читать/писать без автоматической
замены EOL. BOM сохранять по исходному файлу; не назначать UTF-8 без BOM всему
проекту только потому, что это обычная настройка редактора.

При нечитаемой кириллице сначала определить, повреждены ли байты или только
отображение консоли. Не «исправлять» рабочий файл перекодированием наугад.
Редактор нового файла должен воспроизводить формат ближайшего эталона.

## Слияние и фиксация

Слияние XML — проверка модели, а не только удаление маркеров конфликтов.
Проверить состав владельца, ссылки, UUID и внутренние типы. Затем платформенный
цикл. Включать в коммит только порученные изменения, не захватывать чужие
незакоммиченные файлы. Не выполнять force-push или очистку проекта без задачи.

Pull получает файлы; сравнение с текущей ИБ, загрузка и обновление БД выполняются
отдельно. Разрешение на Git-операцию не означает выбор рабочей ИБ для загрузки.
