# Синтакс-помощник и проверка API

## Доказательство вызова

До нового или сомнительного вызова установить:

1. Точный тип получателя/глобальный контекст.
2. Реальное имя метода/свойства/значения перечисления.
3. Перегрузку, порядок параметров, обязательность, режим передачи.
4. Тип результата, побочные эффекты, возможные исключения.
5. Контекст: клиент/сервер/внешнее соединение/обычное приложение.
6. Минимальную версию и ограничения совместимости.

Имя, похожее на БСП или API платформы, не является доказательством существования.
Метод коллекции платформы и метод прикладного объекта могут называться одинаково.

## Порядок источников

| Вопрос | Приоритет |
|---|---|
| Прикладной метод, БСП | Определение и вызовы в текущей выгрузке |
| API платформы | Синтакс-помощник целевой установленной сборки |
| Стандарт/методика | Доступная официальная документация 1С/ИТС |
| Инструмент | Документация и `--help` установленной версии |
| Практический приём | Авторский репозиторий/статья после сверки с первоисточником |

Если сведения конфликтуют, показать версии и точную разницу. Не объявлять
текущую интернет-справку подходящей к старой платформе автоматически.

## Работа с локальной справкой

Конфигуратор даёт синтакс-помощник интерактивно. Файлы семейства `shcntx_*.hbk`,
`shlang_*.hbk`, `shquery_*.hbk` можно использовать через проверенный парсер/индекс,
поддерживающий формат конкретной версии. Не читать HBK как обычный UTF-8 файл,
не обещать извлечение простым поиском строк.

Доступные варианты для изучения: `1c-syntax/bsl-context` (парсер справки),
`Regsorm/bsl-context` и `Desko77/mcp-bsl-platform-help-context` (MCP-контекст).
Это внешние проекты, они не встроены в комплект. Проверять установку, версию
данных, лицензию и реальные схемы инструментов. Не скачивать/публиковать чужую
поставку HBK вместе со скиллом.

Индекс строить для нужной сборки, отмечать её в результате. Искать точный
символ, затем открывать карточку; при нескольких совпадениях уточнить тип.
Кешировать найденные карточки в рамках версии, а не навсегда.

## MCP

Сначала обнаружить реально доступные инструменты, затем читать их описание
и схему параметров. Имена `search`, `info`, `get_member` встречаются в отдельных
серверах, но не являются единым API всех MCP. Не вызывать выдуманный endpoint.
Проверить версию платформы индекса, контекст, лимиты результата и флаги
неполного анализа. Пустой результат при неготовом индексе не значит «ошибок нет».

Для справочной задачи отправлять название типа/метода. Передача целого закрытого
модуля внешнему сервису требует допустимого для проекта способа работы с кодом;
предпочитать локальные анализаторы. Наличие MCP не означает разрешение менять ИБ.

## Нет справки или доступа к ИТС

Продолжить анализ известных частей. Найти подтверждённый аналог в проекте;
указать, что не подтверждено в точной версии. Для критичного вызова подготовить
короткую проверку в тестовой 1С или запросить соответствующий фрагмент справки.
Не утверждать, что закрытый раздел прочитан, если видна только страница входа.
Не заменять отсутствующую сигнатуру правдоподобной выдумкой.

Скилл задаёт процедуру поиска знаний; он не содержит полную базу ИТС или весь
синтакс-помощник и не даёт к ним доступ сам по себе.
