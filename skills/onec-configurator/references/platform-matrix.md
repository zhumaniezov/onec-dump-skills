# Матрица платформы и совместимости

Не существует одного номера «версии проекта». Перед сборкой зафиксировать:

| Факт | Где получить | На что влияет |
|---|---|---|
| Полная сборка платформы | Выбранный исполняемый файл и сведения о нём | CLI, компилятор, исправления |
| Режим совместимости | Configuration/Properties/CompatibilityMode | Доступные возможности и поведение |
| Версия XML-выгрузки | Корневой version, ConfigDumpInfo | Допустимая структура и сериализация |
| Версия конфигурации | Properties/Version | Прикладной контракт |
| Версия БСП | Исходники/сведения конфигурации | Сигнатуры и минимальные требования |
| Клиент, ОС, СУБД, режим ИБ | Профиль выбранного стенда | Контексты, UI, блокировки и планы запросов |

Составить строки для основной конфигурации, каждого расширения и тестового
движка. EPF/ERF тоже имеют XML-формат и контексты, хотя собственной конфигурации
БД у них нет. Не выводить одну величину арифметически из другой.

## Несколько веток платформы

Для 8.3.18, 8.3.27 и 8.5.1 создавать отдельные профили и отчёты. Поддержка одной
ветки не доказывает работу другой. Старый проект с обычными формами не переводить
на управляемые и не повышать совместимость ради инструмента.

Новый синтаксис, свойство метаданных, аннотацию расширения или CLI-ключ проверить
по руководству **целевой сборки**. Если проверка отсутствует — оставить not_run
и использовать экспортированный этой платформой аналог. Не брать новейший
генератор как основание для изменения XML-формата старой конфигурации.

Обновление БСП — самостоятельная миграция. В официальной инструкции обновления
для БСП 3.1.11/3.1.12 указаны требования к платформе и совместимости; это не
характеристика любой БСП 3.1. Сначала сверить фактический релиз и раздел
«Переход на новую версию». Публичный ssl_3_1 пригоден для поиска, но его HEAD
не обязан соответствовать библиотеке пользователя.

## Когда разрешён полный вывод «проверено»

Для каждой заявленной комбинации нужны свежие результаты: загрузка XML,
проверка модулей нужных контекстов, обновление тестовой БД, применимость
расширений, прикладные тесты. При изменении сериализации — обратная выгрузка
той же платформой. Для клиент-серверного решения добавить серверную СУБД:
успех файловой базы не доказывает корректность конкурентных транзакций.

Источники: [руководства 1С](https://its.1c.ru/db/v8327doc),
[инструкция обновления БСП](https://its.1c.ru/db/content/updlib/src/bsp/3.1/updatessl_3.1.html).
При закрытом разделе указать ограничение доступа, не выдавать оглавление за
прочитанную документацию.
