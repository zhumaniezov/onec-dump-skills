# Генераторы и редакторы исходников: onec_gen.py

Когда читать: нужно создать или изменить объект метаданных, форму, СКД, роль, макет,
подсистему, пакет XDTO, расширение (заимствование, перехватчик), внешнюю обработку или отчёт —
не руками в XML, а командой. Для точечной правки текста модуля или одного свойства подходит и
`source_edit.py` (source-edit.md).

## Как вызывать

```text
python "${CLAUDE_SKILL_DIR}/scripts/onec_gen.py" list                       команды
python "${CLAUDE_SKILL_DIR}/scripts/onec_gen.py" <область> <действие> <параметры>
python "${CLAUDE_SKILL_DIR}/scripts/onec_gen.py" <область> <действие> <параметры> --dry-run
python "${CLAUDE_SKILL_DIR}/scripts/onec_gen.py" undo [запуск]
python "${CLAUDE_SKILL_DIR}/scripts/onec_gen.py" doctor
```

Параметры команды (`-ObjectPath`, `-Operation`, `-Value`, `-JsonPath`, ...) и форматы описаний
JSON — в справке команды `references/gen/<область>-<действие>.md` (читать только нужную) и в
`references/gen/spec-*.md` (формат JSON: object, form, dcs, sheet, role, xdto). Пути — относительно
текущего каталога или абсолютные, в кавычках.

## Команды

| Область | Действия | Что это |
|---|---|---|
| `object` | `new`, `edit`, `info`, `check`, `draft`, `remove` | Объекты метаданных: справочники, документы, регистры, перечисления, общие модули... |
| `config` | `new`, `edit`, `info`, `check` | Конфигурация (`Configuration.xml`) |
| `ext` | `new`, `borrow`, `intercept`, `diff`, `check` | Расширение: каркас, заимствование объектов, перехватчики методов, сверка |
| `epf`, `erf` | `new`, `check` | Внешние обработки и отчёты (каркас и проверка XML; сборка файла — `onec_env.py profile epf-build`) |
| `form` | `new`, `build`, `edit`, `info`, `check`, `draft`, `remove` | Управляемые формы. Обычные формы (`Form.bin`) — `ordinary_form.py` (navigation.md) |
| `dcs` | `build`, `edit`, `info`, `check`, `draft` | Схемы компоновки данных |
| `role` | `new`, `edit`, `info`, `check` | Роли и права |
| `sheet` | `build`, `info`, `check`, `draft` | Табличные макеты (печатные формы) |
| `template` | `add`, `remove` | Макеты объекта |
| `subsystem`, `cmdui` | `new`, `edit`, `info`, `check` / `edit`, `check` | Подсистемы и командный интерфейс |
| `xdto` | `new`, `edit`, `info`, `check`, `draft` | Пакеты XDTO |
| `help`, `support` | `add` / `set` | Встроенная справка; режим поддержки объекта |

`draft` — получить JSON-описание существующего объекта, формы, СКД или макета: образец для `new`
или `build`. Для формы из 5+ элементов сначала `form draft` похожей формы проекта.

## Порядок работы

1. Найти аналог в проекте (navigation.md) и решить, что создаётся, а что меняется.
2. Для изменения существующих исходников сначала `--dry-run`: команда выполняется на временной
   копии и показывает diff; права записи в настоящие файлы у движка нет. Копируется вся выгрузка
   (или внешний объект), в том числе для `build` и `draft` внутри неё: движку нужен тот же
   контекст — объект, `Configuration.xml`, версия формата, — и пробный результат совпадает с
   настоящим. Команды `new` собирают каркас во временном каталоге. Крупная выгрузка копируется
   долго — для неё пробный запуск по ситуации.
3. Запуск без `--dry-run`. Движок пишет только туда, что меняет команда: выгрузка, расширение,
   внешний объект, каталог нового файла вне выгрузки, а также дополнительный выходной файл
   (`form build -EmitDsl`); попытка записи в другое место — ошибка `PermissionError`, ничего
   не записано. `form build` в выгрузке может зарегистрировать новую форму в XML объекта — это
   тоже попадает в журнал. Перед первой правкой каждого файла его исходное
   состояние сохраняется в `<проект>/.onec/gen/<запуск>/` (при любом размере выгрузки),
   после записи печатается, что изменено, добавлено и удалено.
4. Проверить результат командой `check` этого же вида (многие команды проверяют сами) и, для
   основной конфигурации и расширений, — на платформе (`onec_env.py profile cf-check | cfe-build`).
5. Не то — `onec_gen.py undo` возвращает исходники к состоянию до запуска, в том числе новые
   каталоги (`config new`, `ext new`, `epf new`). Сначала проверяется всё: файлы не менялись
   после запуска, удалённые не созданы заново, исходные копии целы; при любом расхождении отмена
   отказывает и не трогает ни одного файла — тогда разбирать вручную по журналу или через git.

## Правила

- Изменения основной конфигурации на поддержке, удаление объектов и `config edit` — только в
  объёме задачи; для доработки типовой предпочитать расширение (`ext borrow`, `ext intercept`).
- Перехватчик `Instead` (`&Вместо`) — только если в задаче нужно заменить метод целиком;
  по умолчанию `Before`/`After`, для правки внутри метода — `ModificationAndControl`.
- `ConfigDumpInfo.xml` команды не меняют: если движок его тронул, файл восстанавливается.
- Новые UUID получают только новые сущности; формат выгрузки (`FormatVersion`) для новой
  конфигурации, расширения, обработки — по платформе проекта (2.20 — 8.3.27, 2.21 — 8.5).
- Если файл изменён в обход охраны записи (так быть не должно), запуск завершается с кодом 3 и
  сообщением «ОШИБКА ... отмена этого запуска невозможна»; `undo` такой запуск не отменяет —
  сообщить пользователю и вернуть файлы из git.
- Журналы версий до 3.0.1 `undo` не принимает (их копия могла быть неполной).
- После изменения состава объектов — `onec_index.py build`: индекс подхватит изменения.

## Установка и проверка

Генераторам нужна библиотека lxml: `python -m pip install lxml` (один раз). Без неё команды
`onec_gen.py` отвечают, как её поставить; остальные скрипты скилла работают без неё.
`onec_gen.py doctor` проверяет Python, lxml и целостность движка.

## Движок

Команды выполняет движок `engine/` — Python-версии генераторов открытого проекта (лицензия MIT,
NOTICE.md), перенесённые без изменений из закреплённой ревизии `engine/manifest.json`. Обновление —
только `scripts/sync_engine.py --clone [--commit <ревизия>]`, затем тесты; вручную `engine/` и
`references/gen/` не править. Движок проверен собственным регрессионным набором источника на этой
ревизии; на платформе 1С его результат проверяется так же, как ручная правка: загрузкой и
проверкой Конфигуратором.
