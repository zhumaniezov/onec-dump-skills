# Навигация по выгрузке: индекс и «где используется»

Скрипт `scripts/onec_index.py` (Python 3.9+, только стандартная библиотека) строит
SQLite-индекс выгрузки Конфигуратора и печатает короткие сводки. Вывод ограничен
150 строками, продолжение — `--offset N`.

Индекс хранится вне выгрузки — `%LOCALAPPDATA%\onec-dump\index\` (Windows) или
`~/.cache/onec-dump/index/`, по файлу на выгрузку; `onec_index.py where` покажет путь.
Выгрузку можно удалять и выгружать заново: индекс сохранится, а объекты с тем же
содержимым (новые только даты файлов) повторно не разбираются. Корень ищется в текущей
папке, её родителях и подпапках `cf`, `src/cf`, `src`. Свой каталог — `ONEC_INDEX_DIR`,
свой файл — `--db`.

## Запуск

```text
python "${CLAUDE_SKILL_DIR}/scripts/onec_index.py" build --root "<корень выгрузки>"
python "${CLAUDE_SKILL_DIR}/scripts/onec_index.py" info Справочник.Номенклатура --root "<корень>"
python "${CLAUDE_SKILL_DIR}/scripts/onec_index.py" refs ОбщийМодуль.ОбщегоНазначения --member ЗначениеРеквизитаОбъекта --root "<корень>"
```

Первый `build` крупной конфигурации — минуты, повторные обновляют только изменённые объекты.

## Расширения и внешние обработки/отчёты

Если рядом с выгрузкой лежат выгрузки расширений (`*_extensions`) или внешних обработок и
отчётов (`*_dataprocessors`, `*_externalreports`), подключить их — иначе «где используется»
не увидит доработок в них:

```text
python "${CLAUDE_SKILL_DIR}/scripts/onec_index.py" build --root "<корень>" --with "<каталог расширений>" --with "<каталог внешних>"
```

- Каталоги запоминаются: дальше достаточно `build`. Новый список `--with` заменяет прежний,
  `--no-extras` отключает все.
- В каталоге ищутся выгрузки расширений (`Configuration.xml` с `ConfigurationExtensionPurpose`)
  и внешних объектов (`Имя.xml` с `ExternalDataProcessor`/`ExternalReport`; имя объекта берётся
  из XML, а не из имени файла) — на глубину до трёх уровней.
- `refs` помечает источник: `[расширение X]`, `[внешняя обработка Y]`, `[внешний отчёт Z]`.
  Связь `перехват` — метод объекта перехвачен в расширении (`&Перед`, `&После`, `&Вместо`,
  `&ИзменениеИКонтроль`): `refs ОбщийМодуль.М --member Метод` покажет и вызовы, и перехваты.
- `info` объекта основной конфигурации добавляет строку на каждое расширение: что оно
  добавило (реквизиты, ТЧ, формы, макеты) и какие методы перехватило. Заимствованные без
  изменений реквизиты не повторяются.
- `stats` перечисляет подключённые источники; `find` помечает найденное в них.
- Проверка запросов (`onec_query.py`) учитывает реквизиты, добавленные расширениями, если
  они подключены к индексу. Для файлов расширения или внешнего отчёта указывать
  `--root` основной конфигурации.

## Когда что вызывать

| Вопрос | Команда |
|---|---|
| Что за конфигурация, формат выгрузки, совместимость, объём | `stats` |
| Реквизиты с типами, ТЧ, формы (управляемая/обычная), команды, макеты, модули, движения | `info Документ.Имя` |
| Экспортные методы общего модуля с параметрами | `info ОбщийМодуль.Имя` |
| Права роли / состав подсистемы / источники подписки | `info Роль.Имя`, `info Подсистема.Имя` |
| Кто использует объект (перед изменением, оценка влияния) | `refs Вид.Имя` |
| Кто вызывает метод общего модуля или менеджера | `refs ОбщийМодуль.Имя --member Метод` |
| Только источники одного вида | `refs ... --kind Роль` |
| Каждая связь с номерами строк | `refs ... --detail` |
| Найти по части имени, синонима, имени процедуры | `find подстрока` |

Объекты называются по-русски или по-английски (`Справочник.X`, `Catalog.X`).
Имя без вида допустимо, если однозначно; иначе скрипт перечислит варианты.

## Что индексируется

Объекты всех видов, реквизиты/измерения/ресурсы/ТЧ с типами, значения заполнения,
владельцы, ввод на основании, движения документов, состав подсистем, права ролей
(только `true`), подписки, функциональные опции, определяемые типы, `Form.xml`,
модули объектов, менеджеров, форм, команд и общих модулей, запросы схем СКД
(`Template.xml`) и динамических списков (`Form.xml`) — связи вида `query`. Модуль обычной формы
читается из контейнера `Form.bin`. Строки-комментарии не учитываются.

## Чего индекс не видит

Имена, собранные строкой (`"Справочники." + Имя`), `Выполнить`/`Вычислить`,
раскладку обычной формы. Для таких
случаев дополнить `refs` поиском Grep по имени и явно сказать, что поиск лексический.

## Как отвечать

Сначала итог: сколько источников, каких видов. Затем существенное для задачи.
Сотни связей не перечислять — сгруппировать и предложить `--kind`/`--member`.
Код читать по пути из `info` фрагментом (Read с offset/limit), не целиком.

## Обычные формы (`Form.bin`)

`scripts/ordinary_form.py`:

| Команда | Что делает |
|---|---|
| `info <Form.bin>` | реквизиты формы с типами, события формы, дерево элементов (тип, имя, подпись), обработчики элементов, процедуры модуля без привязки |
| `module <Form.bin> [--out файл.bsl]` | текст модуля формы |
| `set-module <Form.bin> <новый.bsl> --expected-sha256 SHA` | показать diff замены модуля, ничего не записывая |
| то же с `--apply` | записать: запись `form` и отметки времени не меняются, BOM и CRLF как у исходного модуля |
| `verify <Form.bin>` | проверить контейнер: записи, отсутствие сжатия, разбор формы |

Порядок правки модуля обычной формы: `info` (узнать SHA256) → `module --out` →
правка файла → `set-module` без `--apply` (проверить diff) → с `--apply` → `verify`.
При изменившемся файле инструмент отказывает: план перестроить по текущему файлу.

Что известно о формате и где граница:
- Записи `form` (дерево в скобках) и `module` (BSL). Записи не сжимаются: сжатую форму
  платформа 8.3.27 не открывает. Байтовое сравнение после сборки не годится — сравнивать записи.
- Тип элемента определён по GUID класса, сопоставленному с образцами реальных форм;
  «?» в типе — сопоставление по одному образцу.
- Обработчик определяется совпадением строки свойств элемента с именем процедуры модуля.
  Процедуры «без привязки» могут вызываться из кода — проверять поиском, а не удалять.
- Раскладка (координаты, привязки) и остальные числовые свойства не расшифрованы. Менять
  элементы, свойства и раскладку инструментом нельзя: это делается в Конфигураторе.
- Загрузку в ИБ и открытие формы в толстом клиенте проверяет человек.
