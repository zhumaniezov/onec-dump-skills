# Процесс работы

## Паспорт окружения

| Сведения | Где искать |
|---|---|
| Корни выгрузки и расширений | `rg --files`, `Configuration.xml`, структура репозитория |
| Прикладная версия, совместимость, режим | Свойства Configuration |
| Полная сборка платформы | Профиль, установленный `1cv8`, журнал сборки |
| Версия БСП | Реальные общие модули, поставка, история обновления |
| Вид ИБ, клиент, СУБД | Профиль стенда; секреты не публиковать |
| Именование, доработки типовой | CLAUDE.md, правила проекта, аналоги |
| Исходные изменения | `git status --short`, ветка, точечный diff |

Профиль `assets/CLAUDE.onec.example.md` — шаблон, а не установленные факты.
Не назначать версию платформы и префиксы по примеру из документации.

## Бюджет чтения

Сначала список путей и определения, затем вызывающий код. В большом модуле
найти методы и читать конкретные участки. Для запроса прочитать только
участвующие метаданные. Для XML сначала компактная структура, затем точный узел.
После изменения перечитать изменённый участок и связанные контракты.
Кешированный индекс перепроверить по хешу/времени исходников.

```bash
rg --files src -g '*.bsl' -g '*.xml'
rg -n -g '*.bsl' '^(Процедура|Функция) ' src/cf/CommonModules
rg -n -F 'ИмяМетода(' src/cf src/cfe
rg -n -F 'ИмяРеквизита' src/cf/Documents src/cfe
git diff --stat
git diff -- 'src/cf/Documents/Имя/Ext/ObjectModule.bsl'
```

Пути адаптировать после обнаружения layout. Не создавать отсутствующий файл
лишь потому, что ожидался другой способ размещения исходников.

## Карта влияния

Определить владельца метаданных, типы и ограничения; вызовы, подписки и события;
контексты; источники данных, движения, права, обмены; перехваты расширений;
пользовательский сценарий и наблюдаемый критерий результата.
Для ошибки построить цепочку «действие → обработчик → метод → запрос/запись».
Проверить причину до рефакторинга. Не выдавать предполагаемое воспроизведение
за выполненное; сформировать контрольные данные, если симптом зависит от них.

## Решение и уточнения

Для типовой оценить расширение, опубликованный интерфейс/подписку и прямую правку
согласно политике проекта. Расширение не гарантирует доступность нужного механизма
на старой платформе. Неизвестный формат проверить по каркасу тестового
Конфигуратора либо подготовить точную инструкцию по его созданию.

Для MVP выбирать небольшой рабочий путь и указывать долг локального дубля.
Не переносить БСП целиком ради операции и не создавать модуль на каждую функцию.
Уточнять невыводимый бизнес-смысл, разрешение коллизий данных и целевую ИБ.
Обычные решения по стилю/поиску принимать самостоятельно. Независимый анализ
продолжать, пока ожидается ответ на существенный вопрос.

Параллельная работа допустима по независимым областям; один XML/модуль в один
момент правит один исполнитель. Делегирование не нужно для каждой задачи.

## Инструкция для Конфигуратора

Дать таблицу «объект → свойство/реквизит → тип/значение → причина», код с точным
модулем и местом вставки, связанные формы, права и подсистемы. Завершить проверкой
конфигурации, сценарием и повторной выгрузкой. Инструкция не означает, что база
или исходники уже изменены.
