# Контролируемое изменение исходников

`scripts/source_edit.py` меняет текстовые файлы выгрузки по проверяемому плану.
XML не пересериализуется: меняется только нужный диапазон, остальные байты
сохраняются. Сеть, внешние процессы и информационная база не затрагиваются.
Проверка XML — только синтаксис; загрузку, компиляцию и тесты запускать отдельно.
Полный контракт (формат плана, журнал, откат, лимиты) — `docs/source-edit-spec.md`
репозитория; читать при сбое применения или доработке инструмента.

## Порядок

```text
python "${CLAUDE_SKILL_DIR}/scripts/source_edit.py" plan  --project <src/cf> --request change.json --out change.plan.json
python "${CLAUDE_SKILL_DIR}/scripts/source_edit.py" show  --plan change.plan.json
python "${CLAUDE_SKILL_DIR}/scripts/source_edit.py" apply --project <src/cf> --plan change.plan.json --journal <новый каталог>
python "${CLAUDE_SKILL_DIR}/scripts/source_edit.py" apply --project <src/cf> --plan change.plan.json --journal <новый каталог> --apply
```

1. `plan` ничего не меняет, пишет только новый файл плана (не поверх исходника;
   повторный план — под новым именем).
2. `show` — проверить diff глазами.
3. `apply` без `--apply` — сухой прогон: проверяет план и актуальность исходников,
   возвращает `dry_run`, ничего не создаёт. `--journal` обязателен и здесь.
4. `apply --apply` — запись. Журнал — новый каталог вне целевых исходников.

Вывод — JSON в stdout. Коды: `0` успех/проверка пройдена; `1` ошибка применения
(в отчёте откат); `2` неверный ввод или нарушены предусловия, ничего не записано.
`platform_validation` всегда `not_run`.

## Запрос (schema 1)

```json
{"schema": 1, "operations": [
  {"op": "replace-text", "path": "CommonModules/М/Ext/Module.bsl", "expected_sha256": "<64 hex>", "old": "...", "new": "...", "expected_count": 1},
  {"op": "xml-set-property", "path": "Catalogs/Т.xml", "expected_sha256": "<64 hex>", "property": "Comment", "expected_old": "", "new": "..."},
  {"op": "create-text", "path": "CommonModules/М/Ext/New.bsl", "content": "...", "encoding": "utf-8-bom", "eol": "CRLF"}
]}
```

- 1–256 операций, выполняются по порядку. Неизвестные поля и повторные ключи отклоняются.
- `expected_sha256` — SHA256 исходных байтов файла, строчные hex:
  `python -c "import hashlib,pathlib;print(hashlib.sha256(pathlib.Path('<файл>').read_bytes()).hexdigest())"`.
  Несколько операций над одним файлом указывают один и тот же исходный хеш.
- `path` — относительный от `--project`, разделитель `/`, регистр как на диске;
  только `.xml .bsl .os .query`. Без `..`, абсолютных путей, ссылок, `.git`.
  Каталоги не создаются; удаление и переименование не поддерживаются.
- `replace-text`: точный регистрозависимый поиск без регулярных выражений; число
  совпадений строго равно `expected_count`; `old` непустой и содержит исходные окончания строк.
- `create-text`: цель не должна существовать; `encoding` — `utf-8`, `utf-8-bom`,
  `utf-16le-bom`, `utf-16be-bom`; `eol` — `LF`, `CRLF`, `CR`. Создание и правку
  одного файла в одном запросе не смешивать — сразу дать итоговый `content`.
- `xml-set-property`: только прямое скалярное свойство в
  `MetaDataObject → объект → Properties`. `expected_old` сравнивается точно, без trim.
  Свойства дочерних объектов, вложенные элементы, дубли и неоднозначности — отказ.
  `& < >` экранируются сами; UUID, теги и атрибуты не трогаются.

## Кодировка и строки

Сохраняются UTF-8 (с BOM и без), UTF-16LE/BE с BOM; прочие кодировки отклоняются,
BOM сам не добавляется. Новые строки из `new` приводятся к стилю файла; в файл со
смешанными окончаниями строк новые строки не вставляются.

## Если что-то пошло не так

- Отказ из-за хеша: файл изменился. Перестроить план по текущему файлу; не
  подставлять новый хеш вслепую.
- Код `1`: смотреть в отчёте `completed`, `rolled_back`, `rollback_conflicts`
  (внешние правки сохранены, указан путь к резервной копии), `temporary_files`.
  Журнал не удалять до разбора конфликтов.
- Атомарность — для каждого файла отдельно, не для группы. После сбоя питания или
  прерывания сверить файлы с планом и резервными копиями из журнала.
- На время `--apply` не редактировать эти файлы параллельно.

Пример запроса на синтетических данных — `assets/source-edit.example.json`;
хеши в нём не подходят для реального проекта.
