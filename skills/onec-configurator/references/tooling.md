# Инструменты и их ограничения

В 2.0 дополнительно доступны `project_context.py` (индекс/API/doctor),
`source_edit.py` (планируемые точные изменения) и `onec_gen.py`
(генераторы и редакторы исходников, generators.md). Их контракты описаны
в одноимённых тематических разделах маршрута SKILL.md. Инспектор ниже остаётся
только читающим инструментом и не получает скрытых операций записи.

## Локальный инспектор

`scripts/dump_tool.py` — собственный инструмент только для чтения, Python 3.10+,
без сторонних пакетов, сетевого доступа, запуска shell и подключения к 1С.
Выводит JSON в UTF-8 в stdout. Перенаправление вывода создаёт файл средствами
оболочки; отчёты хранить вне проверяемого каталога исходников.

| Команда | Результат |
|---|---|
| `inventory ROOT` | Счётчики расширений, Configuration.xml и свойства, маркеры EDT |
| `inspect FILE.xml` | Ограниченное дерево XML, атрибуты, текст, namespace, BOM/EOL |
| `audit ROOT` | XML parse, кодировка, смешанные EOL, маркеры merge, пропуски |
| `snapshot ROOT` | SHA-256, размер, кодировка, EOL, найденные UUID для каждого файла |
| `compare BEFORE.json AFTER.json` | Добавления/удаления/изменения и признаки для ревью |

```bash
python "${CLAUDE_SKILL_DIR}/scripts/dump_tool.py" inventory "src"
python "${CLAUDE_SKILL_DIR}/scripts/dump_tool.py" inspect "src/cf/Configuration.xml" --limit 60
python "${CLAUDE_SKILL_DIR}/scripts/dump_tool.py" audit "src/cf/Documents/Продажа"
python "${CLAUDE_SKILL_DIR}/scripts/dump_tool.py" snapshot "src/cf" > before.json
# После отдельного изменения/цикла выгрузки:
python "${CLAUDE_SKILL_DIR}/scripts/dump_tool.py" snapshot "src/cf" > after.json
python "${CLAUDE_SKILL_DIR}/scripts/dump_tool.py" compare before.json after.json
```

Примеры перенаправления рассчитаны на Bash/Git Bash. В PowerShell 5.1 учесть
кодировку перенаправления; JSON-манифест нужен UTF-8, а не неявный UTF-16.
Для ручного использования путь выбрать по установке. В SKILL.md Claude Code
подставляет `${CLAUDE_SKILL_DIR}`; это не обязательная переменная обычной оболочки.

## Ограничения инспектора

- `audit`/`snapshot` читают `.xml`, `.bsl`, `.os`, `.query`. Бинарные артефакты
  не разбираются, текст запросов из BSL не извлекается/не проверяется.
- По умолчанию максимум 16 MiB на файл; `--max-mib` меняет лимит. Пропуск —
  `partial`, а не успешная полная проверка. Нет исходников — `no_input`.
- `--limit` ограничивает показ находок/узлов, но не состав снимка. Проверять
  `truncated` и полные счётчики. Для большого JSON-снимка увеличить лимит чтения
  команды compare или сузить область снимков.
- Код 0 означает отсутствие обнаруженной ошибки команды; читать ещё `status`.
  Код 1 — обнаружены ошибки входных файлов; 2 — ошибка вызова/входа.
- UTF-8 и Unicode с BOM поддерживаются; неизвестная кодировка не угадывается
  как CP1251. Это ограничение инструмента, не утверждение о запрете такой кодировки 1С.
- Исключаются каталоги служебных инструментов и ссылки. Снимок сравнивает
  относительные пути; корни до/после должны представлять одну область.
- UUID — подсказка для ревью. Повторы ссылок допустимы; изменения UUID не всегда
  ошибка. Числовые идентификаторы форм автоматически не проверяются.
- DTD/ENTITY не поддерживаются; нет внешних сущностей, XSD/XDTO-валидации,
  разрешения ссылок метаданных, компиляции BSL и запуска платформы.
- Чтение не является атомарным снимком активно изменяемого дерева. На время
  сравнения завершить запись/выгрузку и не запускать второго редактора.

## BSL Language Server

Использовать закреплённую версию из проекта, проверить `--help` и версию Java.
Официальный пример режима анализа:

```bash
java -jar "/tools/bsl-language-server.jar" --analyze --srcDir "src/cf" --reporter json --outputDir "build/bsl-analysis"
```

Пути условные, каталог отчётов создать согласно workflow проекта. Прочитать
фактический отчёт и покрытие анализом, не только код процесса. Учитывать
настройки исключений, baseline и конфигурацию диагностик. Не запускать
форматтер на весь проект ради проверки.

В некоторых версиях есть MCP-режим; наличие в ветке develop не доказывает
наличие в установленном release. Сверять `--help`, официальный README и схемы
инструментов. Без MCP доступен CLI-анализ.
