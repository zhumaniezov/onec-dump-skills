# Создание конфигураций, расширений, обработок и отчётов

## Исходная точка

Выбрать артефакт и контракт до генерации. Обязательные факты: платформа,
совместимость, основная конфигурация, вид клиента, свойства/типы, точка входа,
права, критерий проверки. Не спрашивать повторно, если это есть в проекте.
Для XML сначала использовать эталон **того же формата и версии** из проекта
или каркас, выгруженный установленным Конфигуратором.

## Новая конфигурация

`create-project.example.json` создаёт новую файловую ИБ в каталоге прогона,
выгружает её XML, создаёт пустое расширение и выгружает его. Полученные каркасы
перенести в проект после проверки, затем задать имя/синоним, режимы и совместимость,
добавить подсистемы, объекты, роли и начальное поведение.

Пустой каркас не является готовой прикладной конфигурацией. После добавления
объектов выполнить build-cf, создание начальных данных и прикладные тесты.
Идентификаторы каркаса сохранять между изменениями.

## Новый объект метаданных

1. Выбрать подходящий тип, а не реализовывать штатную сущность набором регистров
   без причины. Определить владельца, измерения/ресурсы, типы, связи и права.
2. Создать каркас в Конфигураторе или по проверенному аналогу.
3. Назначить новые UUID только новым сущностям; сохранить ссылки на существующие.
4. Зарегистрировать объект в составе владельца и необходимых подсистемах/ролях.
5. Добавить модули/формы/команды/макеты с корректными внутренними идентификаторами.
6. Проверить ссылочную целостность, загрузку, поведение и повторную выгрузку.

Создавать и менять объекты, формы, СКД, роли, макеты, расширения — командами
`onec_gen.py` ([generators.md](generators.md)): с пробным запуском, резервной копией и отменой.
Формат описаний JSON — `references/gen/spec-*.md`; не считать его универсальным форматом 1С.
Для точечной правки текста модуля или одного свойства подходит и [source-edit.md](source-edit.md).

## Расширение

Для независимого расширения подходит пустая база; для заимствований нужна
точная основная конфигурация. `build-cfe.example.json` сначала разворачивает её.
Определить назначение, префикс, совместимость, заимствования, перехватчики,
собственные данные и ограничения поддержки. Проверить `До/После/Вместо`,
вызов продолжения, приоритет и сочетание с другими расширениями.

Компиляция CFE не доказывает применимость или вызов обработчика. Установить
в тестовую ИБ, проверить применимость и выполнить наблюдаемый сценарий.
Параметры безопасности тестового движка не переносить на боевое расширение.

## EPF и ERF

В Конфигураторе создать внешнюю обработку или внешний отчёт и выгрузить в файлы;
либо взять соответствующий существующий каркас. Корневой объект должен иметь
тип ExternalDataProcessor или ExternalReport, а не объект конфигурации.
Состав: корневой XML, модуль объекта, формы/их модули, макеты, при необходимости
справка/картинки. ERF со СКД дополнительно требует схемы и настроек компоновки.

Редактирование выполняется по `designer-xml.md`, `forms.md`, `dcs.md`.
Сборка через Конфигуратор/`vrunner epf compile` определяет EPF или ERF по типу
корневого объекта. Имя результирующего файла сверить с корневым XML, не только
с названием каталога. Собирать в отдельный каталог, не поверх исходников.

Проверка EPF: создание/открытие, интерфейс, серверный метод и побочные эффекты.
Проверка ERF: компоновка, контрольные итоги, параметры/варианты, печать/выгрузка.
Для подключения через БСП проверить интерфейс регистрации и безопасный режим
в конкретной версии БСП. Один успешно созданный бинарный файл — только сборка.
