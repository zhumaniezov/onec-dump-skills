# Полный цикл разработки без EDT

## Выбор маршрута

1. **Задача и модель.** Зафиксировать ожидаемое поведение, тип поставки,
   метаданные, зависимости, платформу/совместимость и сценарий проверки.
2. **Тест до изменения.** Для дефекта воспроизвести ошибку; для новой логики
   определить проверяемые результаты. Существующие тесты расширять по месту.
3. **Исходники.** Создать/изменить XML и BSL, проверить связи, права и контексты.
4. **Статика.** Diff, инспектор, BSL LS с принятым baseline. Это быстрый слой.
5. **Сборка.** В выделенной ИБ загрузить XML, проверить Конфигуратором,
   обновить конфигурацию БД, получить ожидаемые CF/CFE/EPF/ERF.
6. **Тесты.** Модульные → интеграционные → ограниченные права → UI по риску.
7. **Повторная выгрузка.** Сравнить идентичность и содержимое затронутой области.
8. **Поставка.** Связать артефакт с ревизией, версиями, отчётами и инструкцией
   установки/отката. Развёртывание в рабочей ИБ определяется заданием отдельно.

При запросе «весь цикл» довести каждый применимый этап до результата. Если нет
платформы/лицензии/стенда, завершить доступную часть и выдать точную команду,
ожидаемый артефакт и непроверенный остаток. Не заменять выполнение тестов их текстом.

## Минимум по типу изменения

| Изменение | Обязательные доказательства по задаче |
|---|---|
| Чистая функция BSL | Граничные случаи, типы, округление, целевой контекст |
| Запрос | Контрольная выборка, кратность/итоги, период, Null, права, объём |
| Регистр/проведение | Движения, повтор, отмена, коллизии, блокировки, конкурентность |
| СКД/отчёт | Детали и итоги, варианты, параметры, расшифровка, права |
| Форма | Видимость/доступность/команда, клиент-сервер, роли, состояние объекта |
| Расширение | Сборка поверх нужной основной, применимость, перехват, порядок |
| EPF/ERF | Сборка файла, создание объекта, выполнение/компоновка в целевой ИБ |
| Обмен/HTTP | Контракт, негативные ответы, повтор, идемпотентность, таймаут |
| OneScript-инфраструктура | Тесты процесса, путей/кодировок, кодов возврата и файлов |

Не создавать десятки тестов на очевидное присваивание. Покрыть бизнес-инвариант,
ошибочный путь и границу, из-за которых изменение может повредить поведение.

## Базовый профиль

`assets/pipelines/full-cycle.example.json` задаёт последовательность для проекта,
где есть основная конфигурация, одно прикладное расширение, EPF, ERF и тесты YAxUnit:
аудит → новая ИБ → загрузка → проверка → обновление БД → CF → CFE → EPF/ERF →
движок/тестовое расширение → применимость → тесты → повторная выгрузка и
байтовое сравнение основной конфигурации, прикладного расширения, EPF и ERF.
В версии 2.0 профиль содержит 32 этапа: четыре исходных снимка и четыре
сравнения после повторной выгрузки. Отличия дают провал соответствующего этапа.
Проверить diff: изменения сериализации и изменения смысла различаются. Не
устранять расхождение автоматической перезаписью исходников. Внешние объекты
выгружаются с подключением к той же тестовой ИБ для разрешения типов.

Это пример состава этапов, а не требование иметь все виды артефактов. Удалить
неприменимые этапы при настройке и отразить фактическое покрытие. Для UI добавить
настроенный профиль Vanessa Automation или существующий инструмент команды;
передать ему ту же **тестовую** ИБ и свежий каталог отчётов. Тестовые расширения
не включать в клиентскую поставку.

Профили используют чистую ИБ. Если конфигурация требует начального заполнения,
обработчиков обновления БСП, пользователей или исходных данных, добавить этап
подготовки с реальным API этой конфигурации до тестов. Не называть пустую ИБ
репрезентативной копией рабочей. Для СУБД/блокировок нужен отдельный серверный стенд.

## Сборка и компиляция

Сериализация XML в CF/CFE/EPF/ERF, синтаксический контроль модулей и компиляция
при выполнении — разные проверки. В 1С нельзя заменить их одним внешним
«компилятором BSL». Проверить нужные клиентские/серверные контексты, не только
возможность получить бинарный файл. Статус CI должен показывать эти уровни отдельно.

CF после `DumpCfg` и файл поставки после `CreateDistributionFiles` имеют разное
назначение в сопровождении. Если нужен дистрибутив/CFU, настроить свойства
поставки и базовые версии; не переименовывать произвольный CF в CFU.
