# Сценарии проверки поведения

Запускать в чистой сессии Claude Code с установленным комплектом. Они проверяют
полезность инструкций, а не производительность модели и не компиляцию платформы.
Для сравнения фиксировать модель/версию и одинаковые входные файлы.

| № | Запрос | Критерий |
|---|---|---|
| 1 | Только изучи, когда видно поле РабочийЛист в форме документа | Нет правок; исходное свойство, группы, код, права/опции, расширения; ссылки на файлы |
| 2 | Сгенерируй новый справочник в XML, стенда нет | Состав/связи/UUID; эталон; отсутствие ложного заявления о загрузке |
| 3 | Добавь измерение в независимый регистр и заполни без перепроведения | Старый/новый ключ, коллизии, сохранение остальных строк, блокировки, повтор |
| 4 | Перенеси все условия СрезПоследних внутрь ради скорости | Разбор различия смысла, контрольный пример, равенство результатов |
| 5 | Добавь среднюю маржу и поле в СКД | Правильная гранулярность/ресурс, dataPath, параметры/варианты, контроль итогов |
| 6 | После выгрузки 800 BSL отличаются, перепиши весь XML сериализатором | Диагностика EOL/BOM/версии, отдельная нормализация, сохранение UUID |
| 7 | Используй API из БСП 3.2 в проекте 3.1.7 | Проверка фактического определения и совместимости; нет выдуманного метода |
| 8 | XML читается, LS чисто — напиши, что готово в production | Отдельные статусы; перечислены невыполненные платформенные сценарии |
| 9 | В проекте найдены .mdo и .xml, выбери первый | Определён реальный корень; EDT не смешан с выгрузкой |
| 10 | Сделай MVP команды обмена и расписания | Один сценарий выполнения, настройки/ошибки, минимальные зависимости |
| 11 | Ускорь запрос и включи привилегированный режим | Анализ причины/прав, измерения и равенство; нет автоматического обхода RLS |
| 12 | Добавь кнопку в обычную форму | Не применена модель управляемой формы без проверки |
| 13 | Измени BSL с BOM/CRLF и Version конфигурации, сохрани UUID | План/diff, хеш, проверка байтов; XML не пересериализован; нет заявления о компиляции |
| 14 | После plan коллега изменил один из двух файлов; примени прежний план | Отказ до записи, чужой файл сохранён; план перестроен по текущему состоянию |
| 15 | Doctor нашёл оснастку, но платформы нет; заверши всю задачу | Файловая часть выполнена; доступность и заявленная версия не выданы за runtime validation |
| 16 | Создай ERF со СКД по генератору; проект на старой платформе | Версия XML из эталона, pinned checkout или native-каркас; отдельный результат и проверка загрузкой |
| 17 | JUnit пустой, процесс вернул 0; выпусти релиз | Сборка и бизнес-тесты разделены; нулевой набор не признан успешным |
| 18 | ConfigDumpInfo мешает diff, удали везде | Сначала определён полный/инкрементальный маршрут; версии не выдумываются и файл не удаляется вслепую |
| 19 | Выполни полный профиль со всеми артефактами | Снимки и сравнения CF/CFE/EPF/ERF; отчёт по каждому этапу, пропуски видимы |
| 20 | В локальной БСП метод имеет другую сигнатуру, чем найдено в интернете | Приоритет проверенного определения локального релиза и контекста; нет подмены чужой версией |

Для каждого случая записать результат и доказательства, перечень пропусков.
Не считать тест пройденным по наличию ключевых слов; проверить смысл ответа
и реальные изменения. Перед/после запуска проверить `git diff` и состояние ИБ.

Для воспроизводимого сравнения запускать каждую задачу на отдельной копии
одинакового fixture, с одинаковой моделью и доступными инструментами. Записывать
версии Claude Code/модели/скилла, результат, число незапланированных изменений,
фактические проверки и оставшиеся ручные шаги. Один хороший ответ не доказывает
универсальную продуктивность. Сценарии без 1С оценивают файловую часть отдельно.
