# onec-dump-skills

Плагин для Claude Code: разработка 1С:Предприятие 8.3 / 8.5 по файловой выгрузке
Конфигуратора (`Configuration.xml`, XML + BSL), без EDT.

Версия **2.6.1** — объединение скилла `onec-configurator` 2.0 и индексатора `onec-dump` 0.1.
Подробности версий — [CHANGELOG.md](CHANGELOG.md), план — [docs/ROADMAP.md](docs/ROADMAP.md).

## Что внутри

Один скилл `onec-configurator`: короткий SKILL.md, справочники подгружаются по задаче.

| Компонент | Назначение |
|---|---|
| `skills/onec-configurator/SKILL.md` | Маршрут работы и выбор справочника |
| `references/` | 30 справочников: XML метаданных, формы, запросы, СКД, регистры, расширения, БСП, тесты, CI... |
| `scripts/onec_index.py` | Индекс выгрузки в SQLite: карточка объекта, «где используется», вызовы метода, поиск; с расширениями и внешними обработками (`--with`) |
| `scripts/onec_query.py` | Запросы модулей, СКД и динамических списков: сверка таблиц и полей, #std657, #std436, #std435 |
| `scripts/onec_std.py` | Стандарты ИТС офлайн (321): пункт, поиск по теме, стандарт по коду АПК / BSL LS / 1C:Code style |
| `scripts/sync_standards.py` | Обновление офлайн-копии стандартов из открытого проекта v8std |
| `standards/` | Офлайн-копия стандартов, у каждого ссылка на ИТС; права — фирма «1С» |
| `scripts/ordinary_form.py` | Обычная форма: элементы, обработчики, реквизиты; правка модуля с проверкой хеша |
| `scripts/v8container.py` | Контейнер `Form.bin`: чтение, распаковка, сборка без сжатия |
| `scripts/source_edit.py` | Точечная правка XML/BSL по плану: diff, проверка хешей, BOM/EOL, журнал |
| `scripts/dump_tool.py` | Инвентаризация и аудит выгрузки, снимки до/после; только чтение |
| `scripts/project_context.py` | Doctor окружения, сигнатуры методов и API БСП |
| `scripts/pipeline.py` | Запуск сборки и тестов по профилю, журналы, JUnit |
| `scripts/generator_bridge.py` | Необязательный адаптер генераторов cc-1c-skills закреплённой ревизии |
| `assets/` | Профили сборки/тестов, шаблоны тестов, GitLab CI, шаблоны правил и `CLAUDE.onec` |

## Требования

- Claude Code.
- Python 3.10+ (на Windows команда `python`), только стандартная библиотека.
- Выгрузка в формате Конфигуратора. Проверено на форматах 2.11 и 2.20; 2.21 (8.5) — без образцов.
- Для сборки и тестов — установленная платформа 1С; для анализа и правки файлов она не нужна.

## Установка

Как плагин (из папки, куда распакован репозиторий):

```
claude --plugin-dir C:\tools\onec-dump-skills
```

Или как скилл проекта: скопировать `skills/onec-configurator` в `.claude/skills/` проекта.

Дополнительно для проекта:

- скопировать `skills/onec-configurator/assets/rules/*.md` в `.claude/rules/` проекта;
- заполнить по образцу `assets/CLAUDE.onec.example.md` параметры проекта (платформа, базы, расширения);
- индекс хранится в папке проекта (`<проект>\.onec\index.sqlite`, над `cf\`); если проект в Git — добавить `.onec/` в `.gitignore`.

## Быстрый старт

Откройте Claude Code в папке выгрузки и попросите: «построй индекс и покажи, где используется
справочник Номенклатура». Первая сборка индекса крупной конфигурации — минуты, дальше секунды.

## Структура папок проекта

Удобно держать всё, что относится к одной базе, в одной рабочей папке и открывать
Claude Code в ней:

```
C:\projects\alfa\
  CLAUDE.md            факты проекта (по образцу assets/CLAUDE.onec.example.md) — не теряется при перевыгрузке
  .onec\               индекс скилла — не теряется при перевыгрузке
  cf\                  выгрузка конфигурации: можно удалять и выгружать заново
  ext\<Имя>\           выгрузки расширений
  epf\<Имя>\           внешние обработки, каждая в своей папке
  erf\<Имя>\           внешние отчёты, каждый в своей папке
```

Выгрузка в эти папки из Конфигуратора (ключи сверить с `designer-cli.md` для своей версии платформы):

```
1cv8 DESIGNER ... /DumpConfigToFiles C:\projects\alfa\cf -Format Hierarchical
1cv8 DESIGNER ... /DumpConfigToFiles C:\projects\alfa\ext\<Имя> -Extension <Имя> -Format Hierarchical
1cv8 DESIGNER ... /DumpExternalDataProcessorOrReportToFiles C:\projects\alfa\epf\<Имя>\<Имя>.xml <файл.epf> -Format Hierarchical
```

Скилл найдёт выгрузку в `cf\` сам; расширения и внешние объекты подключаются один раз:
`onec_index.py build --with ext --with epf --with erf`. Индекс лежит в `.onec\` папки
проекта и переживает перевыгрузку `cf\`. Прежняя раскладка (`alfa`, `alfa_extensions` рядом) тоже работает.

## Принципы

- Скилл короткий, детали в справочниках и скриптах.
- Скрипты печатают сводки, а не сырой XML.
- Правка файлов — через план, проверку хешей и показ diff до записи.
- Разделяются проверки: разбор XML, BSL LS, Конфигуратор, выполнение тестов. Невыполненное помечается `not_run`.
- Загрузку в информационную базу и обновление конфигурации БД делает человек или профиль, явно указанный пользователем.
