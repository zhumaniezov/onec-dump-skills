# Изменения

## 3.0.2 — 2026-11-11

Исправления по аудиту генерации форм:

- `form build -EmitDsl <файл>` больше не падает с `PermissionError`: дополнительный выходной файл
  стал разрешённым местом записи со своей резервной копией, журналом и `undo`.
- Пробный запуск `build` и `draft` внутри выгрузки идёт на копии всей выгрузки, а не только
  каталога файла. Раньше движок терял контекст: `form build -FromObject --dry-run` не находил
  объект, а с `-ObjectPath` писал версию формата 2.17 вместо версии выгрузки.
- Новый файл внутри выгрузки (`form build` и др.) может менять и другие её файлы: `form build`
  регистрирует новую форму в XML объекта. Раньше такая запись блокировалась охраной; теперь
  местом записи для них считается вся выгрузка, изменения в журнале и отменяются `undo`.
- `undo` убирает ровно те каталоги, которые создал запуск (их отмечает охрана записи и сверка
  со снимком), и не трогает пустые каталоги, существовавшие до запуска. Журналы 3.0.1
  по-прежнему отменяются.
- Тесты: в каждом из 38 случаев (все 33 команды, меняющие файлы) добавлено пятое свойство — пробный запуск
  показывает те же файлы с тем же содержимым, что даёт настоящий (новые UUID сравниваются по
  структуре ссылок). Новые случаи: `form build -FromObject` для новой формы, `-EmitDsl` в новый
  и в существующий файл.

## 3.0.1 — 2026-11-11

Исправления по аудиту `onec_gen.py`:

- Резервная копия больше не угадывается по команде и размеру выгрузки. Движок запускается под
  охраной записи (`scripts/onec_gen_guard.py`): перед первой правкой, удалением или переносом
  каждого файла его исходное состояние сохраняется в журнал запуска — при любом размере выгрузки.
  Раньше в выгрузке больше 300 МБ `object remove` удалял файлы объекта без копии, и `undo`
  обрывался на середине, оставляя ссылку на несуществующий объект.
- Запись вне каталога, который меняет команда, запрещена: движок получает `PermissionError`.
  Команды чтения (`info`, `check`) могут писать только отчёт `-OutFile`.
- `--dry-run` у команд `new` (`config new`, `ext new`, `epf new`, `erf new`) больше не создаёт
  файлы: каркас собирается во временном каталоге. Настоящий запуск этих команд пишется в журнал,
  и `undo` убирает созданный каталог.
- `undo` всё проверяет до первой записи: изменённые и добавленные файлы не менялись после запуска,
  удалённые не созданы заново, исходные копии на месте и не повреждены. При расхождении — отказ,
  ни один файл не тронут. Раньше отмена затирала файл, созданный заново после удаления.
- Изменение в обход охраны записи обнаруживается сверкой со снимком: код 3, запуск помечается как
  неотменяемый, `undo` от него отказывается. Журналы версий до 3.0.1 `undo` не принимает.
- `onec_gen.py help add` больше не принимается за справку по `onec_gen.py`.
- `onec_env.py`: профиль через vanessa-runner строится только для платформы с полной сборкой из
  стандартного каталога установки — там её ищет vanessa-runner по `--v8version`. Для платформы,
  заданной путём к нестандартному каталогу, — понятный отказ вместо пустого `--v8version`;
  путь к платформе из стандартного каталога получает сборку из `discover`.
- Тесты: каждая команда, меняющая файлы (35 случаев на выгрузке с объектами, формами, макетами,
  подсистемой, ролью, XDTO, расширением), проверяется на четыре свойства — пробный запуск ничего не
  меняет, журнал покрывает все изменения, `undo` возвращает дерево байт в байт, при чужой правке
  `undo` отказывается без записи. Отдельно — запись вне корня, запись в обход охраны,
  повреждённая копия, отсутствие в движке способов записи, которые охрана не перехватывает.

## 2.8.1 — 2026-11-11

Надёжность — по внешнему ревью кода; на каждый случай есть регрессионный тест.

- Разбор контейнера `Form.bin` строгий: заголовки страниц, адреса в пределах файла,
  фактическое наличие заявленного числа байт, петли в цепочке страниц, имена записей.
  Обрезанная форма больше не проходит `ordinary_form verify` (раньше — «ok»). Проверено на 11
  настоящих формах, в том числе с записями на нескольких страницах.
- `ordinary_form set-module --apply` перепроверяет файл непосредственно перед заменой: если
  его успели изменить, запись отменяется и чужое изменение сохраняется.
- `v8container.py unpack` пишет только внутрь указанного каталога и не перезаписывает файлы
  (раньше имя записи `../x` перезаписывало файл снаружи); `pack` не перезаписывает результат.
- Частичная сборка индекса совпадает с полной: при появлении или удалении объекта
  перечитываются модули, где он упоминается (раньше ссылки на новый общий модуль из старых
  модулей не появлялись, а на удалённый — оставались); переименование файла модуля
  замечается. Формат индекса 7: при первой сборке индекс пересобирается целиком.
- Внешние обработки и отчёты из разных подключённых каталогов с одинаковым именем файла
  больше не вытесняют друг друга: ключ содержит имя каталога (`erf:erf/Продажи/Продажи`),
  он же виден в подписи источника. Повторное расширение с тем же именем — предупреждение.
- Тест правил репозитория: имя и описание скилла, длина `SKILL.md`, заголовки стандартов,
  согласованность версий.
