## Что проверяли

Редактор: реальные CLI plan/show/dry-run/apply, точные и многооперационные правки,
UTF-8/BOM/UTF-16/EOL, XML-escaping, CDATA, пустые/вложенные свойства, неверные
поля/хеши/планы, пути/ссылки/коллизии регистра. Воспроизведены ошибки публикации
и очистки, внешние изменения, откат и конфликт отката. Проверяется сохранение
резервных копий. Атомарность группы файлов при остановке ОС не заявляется.

Контекст: namespace и прямые Properties, отдельные версии, дочерние реквизиты,
многострочный API и аннотации перехвата, русский/английский синтаксис,
строки/комментарии, текстовые ссылки запросов, неизвестная кодировка и пределы
выдачи. Doctor не запускал даже специально подготовленный исполняемый fixture
и не принимал доступность пути за проверку версии.

Адаптер: чистый локальный Git fixture, точный commit/blob, изменённый/
неотслеживаемый скрипт, параметры и пути; свежий результат, неизменность
источника, машинные ошибки. Выполнен отдельный процесс через настоящий pipeline
с новым каталогом. Процесс — маленькая Python-программа с контрактом argv:
он **не имитирует семантику PowerShell или платформы 1С**.

## Исправления RED → GREEN

- Индекс API сохраняет параметр аннотации расширения: имя перехватываемого
  метода больше не теряется при маскировании строк.
- Ошибка входного XML генератора возвращается как контролируемая ошибка.
- Независимое ревью воспроизвело обход изоляции через alias/../source.
  После проверки ссылок используются канонические пути. Регрессии проверяют
  копирование и реальный вызов генератора с сохранностью исходного дерева.
- Сквозной тест воспроизвёл конфликт: pipeline создавал родителя output,
  а генератор требовал новый каталог. Для такого контракта добавлен
  outputs.create_parent=false; обычные профили сохраняют прежнее поведение.
- Form/MXL требуют контекст native-выгрузки вместо молчаливого определения
  XML-формата по умолчанию в пустом каталоге.
- Редактор прошёл собственные отрицательные тесты перед реализацией,
  включая stale preflight, ошибки записи/отката и внешние изменения.

## Границы результатов

XML-fixtures синтетические. Исходники и тестовая ИБ пользователя не предоставлялись.
Реальные сборки CF/CFE/EPF/ERF, режимы 8.3.18/8.3.27/8.5.1, обновление БД,
Vanessa, YAxUnit, OneUnit, обычные/управляемые формы и серверные СУБД не проверены.

Параметры внешних инструментов сверены с первоисточниками. Генераторы закреплены
по commit/blob, но их PowerShell и получаемый XML здесь не исполнялись на платформе.
Профили — настраиваемые стартовые конфигурации. Для runtime нужны точные версии,
лицензированная платформа и разрешённый тестовый стенд.

Ревью и сквозные проверки выполнены отдельным AI-проверяющим с реальным запуском
собственных CLI. Это не проверка активации/поведения скилла в Claude Code и не
измерение прироста продуктивности. Для этого приложены 20 сценариев
tests/scenarios.md, которые нужно выполнить в установленном Claude Code.

Windows junction/quoting/taskkill не проверены нативно. Скрипты не являются
sandbox для недоверенного кода и не защищают от враждебного параллельного писателя.
Ограничения объяснены в references; секреты и рабочие данные в тесты не включены.

## Повторить

Из корня распакованного комплекта:

```text
python -m unittest discover -s .claude/skills/onec-configurator/tests -v
python .claude/skills/onec-configurator/scripts/pipeline.py --config .claude/skills/onec-configurator/assets/pipelines/full-cycle.example.json --project . --run-dir build/plan-only
```

Последняя команда — только план, без создания build/plan-only. Для runtime
настроить копию профиля и запускать с --apply в выбранном стенде.
