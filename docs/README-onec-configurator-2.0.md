# 1C Configurator — Claude Code skill

Версия комплекта: **2.0.0**.

Авторский скилл для полного цикла разработки 1С по файловой выгрузке
Конфигуратора: **XML + BSL, без EDT**. Анализ и проектирование, изменения,
создание объектов, запросы/СКД, сборка CF/CFE/EPF/ERF, модульные/интеграционные
и UI-тесты, проверка повторной выгрузки и подготовка поставки.

Основной файл короткий: Claude подключает предметные инструкции по задаче.
Для обычного анализа достаточно Claude Code и исходников. Инструменты сборки
и тестирования подключаются по необходимости.

## Что изменилось в 2.0

Добавлена работа с исходниками по проверяемому плану: точная замена BSL,
создание текстового файла и изменение прямого скалярного свойства XML.
План показывает diff и исходные SHA256; устаревший план отклоняется.
UTF-8/UTF-16, BOM и окончания строк сохраняются. При обычной ошибке записи
инструмент пытается откатить собственные изменения, сохраняя внешние правки.
Это не транзакция нескольких файлов при аварийном завершении ОС.

Навигация теперь поддержана отдельным инструментом: метаданные, экспортные
методы, сигнатуры и лексические ссылки. Doctor показывает доступность программ
и отделяет заявленную сборку от фактически проверенной. API БСП проверяется
по локальным исходникам нужной версии.

Адаптер генераторов создаёт каркасы CF/CFE/EPF/ERF, объекты, роли, управляемые
формы, СКД и MXL через отдельно установленный cc-1c-skills. Закреплены commit
и байты скриптов; выход — новый каталог. Это дополнительный маршрут:
каркасы собственного Конфигуратора остаются базовым вариантом, особенно для
старых платформ. Генерация XML не означает сборку бинарного файла.

Повторно сверены документация Anthropic, описания 1С/ИТС и 11 предоставленных
проектов/инструментов. Уточнены ConfigDumpInfo, частичная загрузка и раздельный
учёт платформы, совместимости, формата XML и БСП. Источники и ограничения
доступа перечислены в конце комплекта.

## Область знаний

- Метаданные XML, состав объектов, UUID/TypeId, расширения, роли/RLS,
  подписки, планы, бизнес-процессы и регламентные задания.
- BSL, клиент-серверные контексты, обычные и управляемые формы, обработчики,
  типы и исключения, стандарты разработки 1С/ИТС.
- Запросы, виртуальные таблицы, СрезПоследних, границы периода, соединения,
  производительность; СКД, ресурсы, группировки, варианты, детали/итоги.
- Регистры/проведение, замещение записей, транзакции, блокировки и конкуренция.
- БСП, типовые/самописные решения, HTTP/JSON/XDTO, обмены, печать и EPF/ERF.
- Проверка API по синтакс-помощнику нужной версии, локальному индексу HBK
  или доступному MCP; точные сигнатуры БСП — по исходникам проекта.
- Git без EDT: минимальный diff, кодировки/BOM/CRLF, загрузка в ИБ отдельно
  от pull, воспроизводимая сборка и тестирование.

Полные тексты ИТС, HBK, лицензированная платформа и сторонние бинарные движки
в комплект не входят. Скилл объясняет, как получать и проверять эти знания
в доступном окружении, и явно отмечает отсутствие доступа/проверки.

## Установка в проект Claude Code

Если получен Git bundle, распаковать его в новый каталог:

```powershell
git clone .\claude-code-1c-configurator.bundle C:\tools\claude-code-1c-configurator-v2
```

1. Скопировать папку `.claude/skills/onec-configurator` в одноимённое место
   внутри репозитория с выгрузкой 1С.
2. При необходимости добавить 5 файлов из `.claude/rules` к существующим
   правилам проекта. Не заменять всю папку `.claude` и прежние инструкции.
3. Заполнить `CLAUDE.onec.example.md` и перенести его разделы в свой `CLAUDE.md`.
   Не записывать пароли. Неизвестные версии оставить как неизвестные.
4. Открыть проект в Claude Code и вызвать `/onec-configurator` с задачей.

Копирование самого скилла в PowerShell с проверкой существующей установки:

```powershell
$Kit = 'C:\tools\claude-code-1c-configurator-v2'
$Project = 'C:\git\My1CProject'
$Destination = Join-Path $Project '.claude\skills\onec-configurator'
if (Test-Path -LiteralPath $Destination) { throw 'Скилл уже существует: сначала сравните версии.' }
New-Item -ItemType Directory -Path (Split-Path -Parent $Destination) -Force | Out-Null
Copy-Item -LiteralPath (Join-Path $Kit '.claude\skills\onec-configurator') -Destination $Destination -Recurse
```

Для личной установки во все проекты разместить ту же папку в
`~/.claude/skills/onec-configurator`. Профиль конкретной базы и проектные rules
оставить в репозитории проекта. При одновременной личной и проектной установке
сверить, какая версия разрешается Claude Code по его текущим правилам.

Проверка установки: команда `/onec-configurator` доступна, Claude читает
основной файл и выбранные references, понимает, где находится XML-выгрузка.
В этом комплекте нет hooks, автоматической выдачи прав инструментам,
скрытых установщиков или обязательного подключения MCP.

При обновлении 1.0 сравнить папку с новой версией и сохранить собственные правки.
Профили баз и существующий CLAUDE.md автоматически не заменять. Основные
команды inspector/pipeline и schema=1 профилей сохранены.

## Практическое начало

После установки попросить Claude определить корни и прочитать инструкции
проекта. Затем выбрать маршрут:

| Задача | Инструкция внутри скилла |
|---|---|
| Найти API, объект, вызовы, доступность инструментов | `references/project-context.md` |
| Исправить существующие XML/BSL с планом и проверкой baseline | `references/source-edit.md` |
| Создать XML новым генератором в отдельном каталоге | `references/generator-bridge.md` |
| Создать native-каркас или собрать CF/CFE/EPF/ERF | `references/object-creation.md` |
| Выполнить сборку и выбранные тесты | `references/pipeline.md`, `references/testing.md` |

Примеры doctor, генерации ERF и запроса правок находятся в `assets` внутри
скилла. Значения примеров — учебные: пути, версии и SHA заменить фактическими.

```text
/onec-configurator Только изучи src/cf и src/cfe. Найди, от каких условий
```

```text
/onec-configurator Исправь заполнение измерения регистра без перепроведения.
```


## Сборка и тесты

Выбор инструментов зависит от проекта:

| Средство | Роль |
|---|---|
| Конфигуратор / 1cv8 | Форматы 1С, загрузка/выгрузка, проверка и сборка |
| vanessa-runner | Автоматизация команд платформы; профили сверены с v3.0.2 |
| YAxUnit | BSL и интеграционные тесты внутри 1С |
| Vanessa Automation | UI и пользовательские сценарии |
| Vanessa-ADD/xUnit | Существующие наборы проекта; отдельный маршрут от VA |
| OneUnit / 1testrunner | OneScript-скрипты и библиотеки |
| Свои CLI/EPF-тесты | Допустимы при наличии assertions и машинного отчёта |

OneScript не компилирует прикладную конфигурацию 1С и не заменяет её API.
Полученный CF/CFE ещё не доказывает работоспособность всех модулей и сценариев.

Настройка запускателя:

1. Выбрать пример из `.claude/skills/onec-configurator/assets/pipelines`.
2. Скопировать в `tools/1c-pipeline.json` своего проекта.
3. Заменить пути/сборку платформы/имена объектов, проверить CLI установленных
   инструментов и состав этапов. Сохранить только применимые этапы.
4. Проверить план; затем выполнить с `--apply` в разрешённом тестовом окружении.

```text
python .claude/skills/onec-configurator/scripts/pipeline.py --config tools/1c-pipeline.json --project . --run-dir build/run-001
python .claude/skills/onec-configurator/scripts/pipeline.py --config tools/1c-pipeline.json --project . --run-dir build/run-001 --apply
```

Для каждого следующего выполнения нужен новый run directory. Инструмент
останавливает цепочку при ошибке, проверяет свежесть файлов и JUnit, не принимает
ноль выполненных бизнес-тестов за успех. Полный пример создаёт отдельную файловую
ИБ, собирает все четыре вида артефактов, загружает YAxUnit и тестовое расширение,
выполняет тесты, выгружает и сравнивает основную конфигурацию, прикладное
расширение и обе внешние обработки/отчёты. В полном профиле 32 этапа.

Для конфигураций с БСП/начальным заполнением требуется проектный этап подготовки
данных. UI, обычные формы и серверная СУБД проверяются отдельными целевыми
сценариями. Standalone-профили тестов ожидают уже готовую тестовую ИБ.
Настройки тестового движка и тестовые расширения не входят в рабочую поставку.

Подробный контракт: [pipeline.md](.claude/skills/onec-configurator/references/pipeline.md).
Проектирование тестов: [testing.md](.claude/skills/onec-configurator/references/testing.md).

## Проверка самого комплекта

```text
python -m unittest discover -s .claude/skills/onec-configurator/tests -v
```

Результаты автоматических тестов, структурной проверки, планирования профилей,
независимого ревью и сквозных CLI-сценариев приведены в
[VALIDATION.md](docs/VALIDATION.md). Проверки выполняются на Linux/Python 3.12.

**Не выполнялись:** Claude Code CLI, Windows, платформа 1С, реальные сборки
CF/CFE/EPF/ERF и прогоны Vanessa/YAxUnit/OneScript. Поэтому профили являются
документированными стартовыми конфигурациями, которые нужно проверить на своём
стенде. Подробности: [VALIDATION.md](docs/VALIDATION.md).
