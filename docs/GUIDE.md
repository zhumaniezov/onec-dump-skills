# Руководство: установка и работа

Как поставить скилл `onec-configurator`, разложить папки проекта и работать каждый день.
Примеры для Windows; на Linux/macOS команды аналогичные.

## 1. Установка (один раз на компьютер)

Нужны Claude Code, Git и Python 3.10+ (проверить: `python --version`; при установке Python
отметить «Add to PATH»).

```
cd C:\tools
git clone https://github.com/zhumaniezov/onec-dump-skills
xcopy /E /I C:\tools\onec-dump-skills\skills\onec-configurator "%USERPROFILE%\.claude\skills\onec-configurator"
```

Скилл ставится глобально: доступен в Claude Code в любой папке. Проверка: в Claude Code набрать
`/onec` — в подсказке появится `onec-configurator`. Если нет — перезапустить Claude Code.

Скилл работает в **Claude Code** (вкладка Claude Code в приложении или `claude` в терминале).
В Cowork и обычном чате скрипты не достают до файлов на вашем компьютере.

Правила (необязательно): короткие указания, которые включаются сами на файлах `.xml` и `.bsl`:

```
xcopy /I C:\tools\onec-dump-skills\skills\onec-configurator\assets\rules\*.md "%USERPROFILE%\.claude\rules\"
```

`onec-core.md` в этом наборе без привязки к файлам и действует во всех проектах — если не нужно,
не копируйте его.

## 2. Обновление

```
cd C:\tools\onec-dump-skills
git pull
xcopy /E /I /Y skills\onec-configurator "%USERPROFILE%\.claude\skills\onec-configurator"
```

Что изменилось — в [CHANGELOG.md](../CHANGELOG.md). Если в версии сменился формат индекса,
первая сборка пройдёт заново целиком.

## 3. Структура папок проекта

Одна база — одна рабочая папка. Claude Code открывать в ней.

```
C:\projects\alfa\
  CLAUDE.md        факты проекта: платформа, базы, расширения, соглашения
  .onec\           индекс скилла (создаётся сам)
  cf\              выгрузка конфигурации — можно удалять и выгружать заново
  ext\<Имя>\       выгрузки расширений
  epf\<Имя>\       внешние обработки, каждая в своей папке
  erf\<Имя>\       внешние отчёты, каждый в своей папке
```

- `CLAUDE.md` и `.onec\` лежат над `cf\` и не пропадают при перевыгрузке.
- Если папка проекта в Git, добавить в `.gitignore` строку `.onec/`.
- Прежняя раскладка тоже работает: выгрузка прямо в `C:\projects\alfa`, расширения в
  `C:\projects\alfa_extensions` и т.п. Тогда индекс — в `C:\projects\alfa\.onec\`, и при
  удалении папки выгрузки он пропадёт вместе с ней (пересоберётся за минуту).

## 4. Выгрузка из Конфигуратора

В интерфейсе: «Конфигурация → Выгрузить конфигурацию в файлы», формат иерархический.
Из командной строки (ключи сверить с документацией своей версии платформы):

```
1cv8 DESIGNER /S <сервер>\<база> /N <пользователь> /P <пароль> /DumpConfigToFiles C:\projects\alfa\cf -Format Hierarchical
1cv8 DESIGNER ... /DumpConfigToFiles C:\projects\alfa\ext\<Имя> -Extension <Имя> -Format Hierarchical
1cv8 DESIGNER ... /DumpExternalDataProcessorOrReportToFiles C:\projects\alfa\epf\<Имя>\<Имя>.xml <файл.epf> -Format Hierarchical
1cv8 DESIGNER ... /DumpExternalDataProcessorOrReportToFiles C:\projects\alfa\erf\<Имя>\<Имя>.xml <файл.erf> -Format Hierarchical
```

Скилл понимает выгрузку Конфигуратора (`Configuration.xml`), не проект EDT.

## 5. Первый запуск в проекте

1. Скопировать `assets\CLAUDE.onec.example.md` из скилла в `C:\projects\alfa\CLAUDE.md` и
   вписать факты: сборка платформы, режим совместимости, базы для проверки, расширения,
   префиксы имён (`adm_`, `uzb_` …). Агенту не придётся каждый раз это выяснять.
2. Открыть Claude Code в `C:\projects\alfa` и написать:
   > Построй индекс и подключи ext, epf и erf.

   Агент выполнит `onec_index.py build --with ext --with epf --with erf`. Крупная конфигурация
   (≈8 тыс. объектов) — около 40 секунд. Подключённые папки запоминаются.

## 6. Каждый день

- После перевыгрузки ничего делать не нужно: перед поиском агент запускает сборку индекса,
  она разбирает только изменённые объекты (у которых поменялась лишь дата файла — нет).
  Если агент этого не сделал, скажите «обнови индекс».
- Новое расширение или обработка в `ext\`, `epf\`, `erf\` подхватятся при следующей сборке.
- Где лежит индекс: «где индекс?» — агент выполнит `onec_index.py where`.

### Что можно спросить

| Задача | Пример запроса |
|---|---|
| Где используется | «Где используется справочник Номенклатура?», «Кто вызывает ОбщегоНазначения.ЗначениеРеквизитаОбъекта?» |
| Карточка объекта | «Покажи реквизиты и табличные части документа ЗаказНаряд» |
| Расширения | «Что расширение ЛокализацияУзбекистан меняет в справочнике Контрагенты?» |
| Запросы | «Проверь запросы в документе ЗаказНаряд», «Проверь запросы отчёта adm_ОтчетАвтосалона» |
| Стандарты | «Что говорит стандарт про запросы в цикле?», «Какой стандарт стоит за ошибкой АПК 254?» |
| Обычные формы | «Покажи элементы и обработчики обычной формы …», «Добавь в модуль обычной формы …» |
| Правка | «Добавь реквизит … в справочник …» — агент покажет план и diff до записи |
| Ревью | «Сделай ревью изменений по стандартам» |

## 7. Чего скилл не делает

- Не загружает изменения в информационную базу и не обновляет конфигурацию БД — это шаг
  человека в Конфигураторе (или профиль `pipeline.py`, который вы явно запускаете).
- Не проверяет компиляцию и работу на платформе: разбор XML и проверки скриптов не заменяют
  Конфигуратор и тесты. Агент отмечает такие проверки как `not_run`.
- Индекс не видит имена, собранные строкой (`"Справочники." + Имя`), и `Выполнить`/`Вычислить` —
  агент дополняет поиском по тексту.

## 8. Частые проблемы

| Проблема | Что сделать |
|---|---|
| `/onec` не находит скилл | Проверить, что работаете в Claude Code, а не в Cowork; перезапустить Claude Code; проверить файл `%USERPROFILE%\.claude\skills\onec-configurator\SKILL.md` |
| Агент пишет, что Python не найден | `python --version`; переустановить Python с «Add to PATH» |
| «Не найден Configuration.xml» | Открыть Claude Code в папке проекта или выгрузки; выгрузка должна быть в формате Конфигуратора |
| Индекс не видит расширение | «Пересобери индекс с подключением ext» — `build --with ext` |
| Сменили структуру папок | Пересобрать индекс; старую папку `.onec` в прежнем месте можно удалить |
