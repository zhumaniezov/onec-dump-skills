# Руководство: установка и работа

Как поставить скилл `onec-configurator`, разложить папки проекта и работать каждый день.
Примеры для Windows; на Linux/macOS команды аналогичные.

## 1. Установка (один раз на компьютер)

Нужны Claude Code и Python 3.10+ (проверить: `python --version`; при установке Python отметить
«Add to PATH»). Для создания и правки объектов, форм и расширений ещё один раз:
`python -m pip install lxml`. Скилл работает в **Claude Code** (вкладка Claude Code в приложении или `claude`
в терминале). В Cowork и обычном чате скрипты не достают до файлов на вашем компьютере.

Есть два способа. Выберите один: если поставить оба, скилл появится дважды.

### Способ А: плагин (рекомендуется)

Устанавливается и обновляется командами Claude Code, Git не нужен. В сессии Claude Code:

```
/plugin install onec-dump --marketplace zhumaniezov/onec-dump-skills
```

То же из терминала: `claude plugin install onec-dump --marketplace zhumaniezov/onec-dump-skills`.
Старые версии Claude Code понимают только двухшаговый вариант:

```
/plugin marketplace add zhumaniezov/onec-dump-skills
/plugin install onec-dump@onec-dump-skills
```

После установки перезапустить Claude Code. Скилл называется `onec-dump:onec-configurator`.

Если раньше скилл был поставлен копированием (способ Б), удалите копию:
`rmdir /S /Q "%USERPROFILE%\.claude\skills\onec-configurator"`.

### Способ Б: копия папки скилла

Нужен Git.

```
cd C:\tools
git clone https://github.com/zhumaniezov/onec-dump-skills
xcopy /E /I C:\tools\onec-dump-skills\skills\onec-configurator "%USERPROFILE%\.claude\skills\onec-configurator"
```

### Проверка

В Claude Code набрать `/onec` — в подсказке появится `onec-configurator`. Если нет —
перезапустить Claude Code.

### Правила (необязательно)

Короткие указания, которые включаются сами на файлах `.xml` и `.bsl`. Плагин их не ставит,
копируются вручную из клона репозитория:

```
xcopy /I C:\tools\onec-dump-skills\skills\onec-configurator\assets\rules\*.md "%USERPROFILE%\.claude\rules\"
```

`onec-core.md` в этом наборе без привязки к файлам и действует во всех проектах — если не нужно,
не копируйте его.

## 2. Обновление

Способ А (плагин):

```
/plugin marketplace update onec-dump-skills
/plugin update onec-dump@onec-dump-skills
```

и перезапустить Claude Code. Можно включить автообновление: `/plugin` → вкладка Marketplaces →
`onec-dump-skills`. Для сторонних каталогов оно по умолчанию выключено.

Способ Б (копия):

```
cd C:\tools\onec-dump-skills
git pull
xcopy /E /I /Y skills\onec-configurator "%USERPROFILE%\.claude\skills\onec-configurator"
```

Что изменилось — в [CHANGELOG.md](../CHANGELOG.md). Если в версии сменился формат индекса,
первая сборка пройдёт заново целиком.

## 3. Структура папок проекта

Одна база — одна рабочая папка. Claude Code открывать в ней.

```
C:\projects\alfa\
  CLAUDE.md        факты проекта: платформа, базы, расширения, соглашения
  .onec\           служебная папка скилла: индекс, настройка тестовой базы, профили, резервные копии
  build\           результаты сборок и проверок (создаётся при запуске)
  cf\              выгрузка конфигурации — можно удалять и выгружать заново
  ext\<Имя>\       выгрузки расширений
  epf\<Имя>\       внешние обработки, каждая в своей папке
  erf\<Имя>\       внешние отчёты, каждый в своей папке
```

- `CLAUDE.md` и `.onec\` лежат над `cf\` и не пропадают при перевыгрузке.
- Если папка проекта в Git, добавить в `.gitignore` строки `.onec/` и `build/`.
- Прежняя раскладка тоже работает: выгрузка прямо в `C:\projects\alfa`, расширения в
  `C:\projects\alfa_extensions` и т.п. Тогда индекс — в `C:\projects\alfa\.onec\`, и при
  удалении папки выгрузки он пропадёт вместе с ней (пересоберётся за минуту).

## 4. Выгрузка из Конфигуратора

В интерфейсе: «Конфигурация → Выгрузить конфигурацию в файлы», формат иерархический.
Из командной строки (ключи сверить с документацией своей версии платформы):

```
1cv8 DESIGNER /S <сервер>\<база> /N <пользователь> /P <пароль> /DumpConfigToFiles C:\projects\alfa\cf -Format Hierarchical
1cv8 DESIGNER ... /DumpConfigToFiles C:\projects\alfa\ext\<Имя> -Extension <Имя> -Format Hierarchical
1cv8 DESIGNER ... /DumpExternalDataProcessorOrReportToFiles C:\projects\alfa\epf\<Имя>\<Имя>.xml <файл.epf> -Format Hierarchical
1cv8 DESIGNER ... /DumpExternalDataProcessorOrReportToFiles C:\projects\alfa\erf\<Имя>\<Имя>.xml <файл.erf> -Format Hierarchical
```

Скилл понимает выгрузку Конфигуратора (`Configuration.xml`), не проект EDT.

## 5. Первый запуск в проекте

1. Скопировать `assets\CLAUDE.onec.example.md` из скилла в `C:\projects\alfa\CLAUDE.md` и
   вписать факты: сборка платформы, режим совместимости, базы для проверки, расширения,
   префиксы имён (`adm_`, `uzb_` …). Агенту не придётся каждый раз это выяснять.
2. Открыть Claude Code в `C:\projects\alfa` и написать:
   > Построй индекс и подключи ext, epf и erf.

   Агент выполнит `onec_index.py build --with ext --with epf --with erf`. Крупная конфигурация
   (≈8 тыс. объектов) — около 40 секунд. Подключённые папки запоминаются.

## 6. Каждый день

- После перевыгрузки ничего делать не нужно: перед поиском агент запускает сборку индекса,
  она разбирает только изменённые объекты (у которых поменялась лишь дата файла — нет).
  Если агент этого не сделал, скажите «обнови индекс».
- Новое расширение или обработка в `ext\`, `epf\`, `erf\` подхватятся при следующей сборке.
- Где лежит индекс: «где индекс?» — агент выполнит `onec_index.py where`.

### Что можно спросить

| Задача | Пример запроса |
|---|---|
| Где используется | «Где используется справочник Номенклатура?», «Кто вызывает ОбщегоНазначения.ЗначениеРеквизитаОбъекта?» |
| Карточка объекта | «Покажи реквизиты и табличные части документа ЗаказНаряд» |
| Расширения | «Что расширение ЛокализацияУзбекистан меняет в справочнике Контрагенты?» |
| Запросы | «Проверь запросы в документе ЗаказНаряд», «Проверь запросы отчёта adm_ОтчетАвтосалона» |
| Стандарты | «Что говорит стандарт про запросы в цикле?», «Какой стандарт стоит за ошибкой АПК 254?» |
| Обычные формы | «Покажи элементы и обработчики обычной формы …», «Добавь в модуль обычной формы …» |
| Правка | «Добавь реквизит Вес в справочник Номенклатура», «Добавь табличную часть …» — агент сначала покажет изменения на копии |
| Создание | «Создай справочник …», «Сделай форму списка …», «Новая роль с правами на …», «Внешняя обработка …» |
| Расширение | «Заимствуй справочник Контрагенты в расширение Доработки и сделай перехватчик ПередЗаписью» |
| Отмена | «Отмени последнее изменение генератором» — вернёт файлы, как были до запуска |
| Ревью | «Сделай ревью изменений по стандартам» |

## 7. Сборка и проверка на платформе

Нужны установленная платформа 1С и **тестовая** база — копия, которую не жалко. OneScript не нужен.
Конфигуратор этой базы на время запуска должен быть закрыт.

Один раз в проекте:

> Найди платформу и базы. Тестовая база — «Альфа тест».

Агент выполнит `onec_env.py discover`, покажет найденные версии платформы и список баз и запишет
выбор в `.onec\env.json` и в `CLAUDE.md`. Базу называете вы: сам агент её не выбирает, потому что
загрузка заменяет конфигурацию базы. Если версий платформы, подходящих к формату выгрузки,
несколько, агент спросит, какую взять.

Если у пользователя базы есть пароль, задайте его переменной окружения и назовите агенту имя
переменной (сам пароль в чат не пишите):

```
setx ONEC_IB_PASSWORD "пароль"
```

После `setx` перезапустите Claude Code.

Дальше — обычные просьбы:

| Просьба | Что делает агент |
|---|---|
| «Проверь на платформе» | Загружает `cf\` в тестовую базу и запускает проверку Конфигуратора |
| «Собери cf» | То же и выгружает `.cf` в `build\cf-build-NNN\` |
| «Собери расширение Имя» | Загружает, проверяет и выгружает `.cfe` |
| «Собери обработки» | Собирает `.epf`/`.erf` из `epf\` и `erf\` в `build\epf-build-NNN\out\` |
| «Обнови тестовую базу» | Добавляет обновление конфигурации БД, чтобы проверить руками в режиме предприятия |
| «Загрузи только изменённое» | Частичная загрузка изменённых файлов вместо полной |
| «Запусти тесты YAxUnit из расширения Имя» | Запускает тесты, если движок и тесты уже загружены в базу |

Перед запуском агент показывает план: какие команды и в какую базу. Полная загрузка крупной
конфигурации идёт долго; журналы каждого шага лежат в `build\<запуск>\`.

Если ваша команда работает через vanessa-runner, скажите: «собирай через vanessa-runner». Агент
запишет его исполнителем по умолчанию (`setup --runner vrunner`), и все просьбы из таблицы будут
выполняться через него. Нужны OneScript и vanessa-runner 3.x (раздел 8); без них — через `1cv8`.

«Протестируй» работает, только если в проекте есть автотесты. Если их нет, агент выполнит
проверку Конфигуратором, скажет об этом и даст шаги ручной проверки.

Эти профили проверены на заглушке платформы, не на настоящей 1С. Первый запуск делайте на
копии базы; если шаг упадёт, агент покажет журнал платформы.

## 8. Дополнительные инструменты: что обязательно

Обязательны только Python и, для проверки и сборки, платформа 1С. Всё остальное нужно для
отдельных задач; скилл сам ничего не устанавливает.

| Инструмент | Для чего | Нужен ли | Где взять |
|---|---|---|---|
| Python 3.10+ | Скрипты скилла | **Обязательно** | python.org, при установке отметить «Add to PATH» |
| lxml (библиотека Python) | Генераторы: создание и правка объектов, форм, СКД, ролей, заимствование в расширение, перехватчики | Только для них | Один раз: `python -m pip install lxml` |
| Платформа 1С и тестовая база | Проверка, сборка, автотесты | Для этих задач; для анализа и правки файлов — нет | Ваш дистрибутив 1С |
| OneScript | Запуск скриптов `.os`: нужен vanessa-runner и OneUnit | Нет | Установщик на oscript.io или в выпусках github.com/EvilBeaver/OneScript; вместе с ним ставится менеджер пакетов `opm` |
| vanessa-runner | Сборка и проверка через vanessa-runner, если команда к нему привыкла; шаблоны полного цикла в `assets/pipelines`; CI | Нет: без него проверку и сборку делает `onec_env.py` одним `1cv8` (раздел 7) | `opm install vanessa-runner` после OneScript; версия 3.x требует OneScript 2.0+. Шаблоны написаны под 3.0.2 |
| YAxUnit | Модульные тесты кода 1С | Только для «запусти тесты YAxUnit» | Выпуски github.com/bia-technologies/yaxunit: расширение `.cfe`, загружается в тестовую базу. Запуск — профилем `yaxunit` без OneScript |
| Vanessa Automation | Сценарные тесты интерфейса (что делает пользователь) | Только для UI-тестов | Выпуски github.com/Pr-Mex/vanessa-automation: архив с `vanessa-automation.epf`, установка не нужна — открывается в тестовой базе |
| BSL Language Server | Статический анализ BSL по правилам | Нет | Выпуски github.com/1c-syntax/bsl-language-server; требования к Java — в README проекта |

С чего начать, если захочется автотестов: YAxUnit — проще всего начать с модульных тестов
общих модулей и запросов. Vanessa Automation — позже, для ключевых пользовательских сценариев.
OneScript и vanessa-runner — когда понадобится сборка на сервере CI или полный цикл из шаблонов.

Версии сверяйте с документацией своих выпусков: у vanessa-runner 2.x и 3.x разные команды,
а Vanessa-ADD и Vanessa Automation — разные проекты. Агент может сказать, что уже установлено:
«что из инструментов 1С у меня есть?» — выполнит `onec_env.py discover`.

## 9. Чего скилл не делает

- Не загружает изменения в рабочую базу. В тестовую — только по вашей просьбе и в ту базу,
  которую вы назвали (раздел 7).
- Без запуска на платформе не проверяет компиляцию и работу: разбор XML и проверки скриптов не
  заменяют Конфигуратор и тесты. Агент отмечает такие проверки как `not_run`.
- Индекс не видит имена, собранные строкой (`"Справочники." + Имя`), и `Выполнить`/`Вычислить` —
  агент дополняет поиском по тексту.

## 10. Частые проблемы

| Проблема | Что сделать |
|---|---|
| `/onec` не находит скилл | Проверить, что работаете в Claude Code, а не в Cowork; перезапустить Claude Code; для плагина — `/plugin` → Installed, для копии — файл `%USERPROFILE%\.claude\skills\onec-configurator\SKILL.md` |
| Скилл в списке дважды | Поставлены и плагин, и копия — удалить копию (раздел 1) |
| Агент пишет, что Python не найден | `python --version`; переустановить Python с «Add to PATH» |
| Агент пишет, что нужен lxml | `python -m pip install lxml`, затем повторить просьбу |
| «Не найден Configuration.xml» | Открыть Claude Code в папке проекта или выгрузки; выгрузка должна быть в формате Конфигуратора |
| Индекс не видит расширение | «Пересобери индекс с подключением ext» — `build --with ext` |
| Платформа или база не найдены | Нестандартный каталог установки: «платформа лежит в `D:\1C`» — агент передаст `--platform-dir`; базу можно назвать путём к каталогу |
| Шаг сборки упал | Попросить «покажи журнал шага» — агент выполнит `onec_env.py log`; частая причина — база открыта в Конфигураторе |
| Сменили структуру папок | Пересобрать индекс; старую папку `.onec` в прежнем месте можно удалить |
