# Дорожная карта

Цель: плагин Claude Code для выгрузки конфигурации 1С в формате Конфигуратора. Читать, находить связи, понимать запросы и формы, сверяться со стандартами, безопасно править XML. Конфигурации ERP-класса (Альфа-Авто, УНФ, ERP, ЗУП, Бухгалтерия), платформа 8.3.27 и 8.5.

## Архитектура (с версии 2.1)

Один скилл `onec-configurator`: короткий маршрут в SKILL.md, 30+ справочников по задаче,
инструменты в `scripts/`. Отдельные скиллы не заводятся, пока объём справочников это
позволяет: так у агента одна точка входа и один листинг-описание.

| Направление | Где | Состояние |
|---|---|---|
| Навигация, «где используется» | `onec_index.py`, `navigation.md` | готово |
| Обычные формы `Form.bin` | `ordinary_form.py`, `v8container.py` | готово: сводка, правка модуля; загрузка в 1С не проверена |
| Безопасная правка XML/BSL | `source_edit.py`, `source-edit.md` | готово (автор onec-configurator) |
| Сборка и тесты | `pipeline.py`, профили в `assets/` | готово, на платформе не прогонялось |
| Запросы и СКД | `onec_query.py`, `queries.md`, `dcs.md` | готово: извлечение, сверка с метаданными, 5 правил |
| Стандарты офлайн | `standards/`, `onec_std.py`, `sync_standards.py` | готово: 321 стандарт, поиск, коды проверок |

## Фазы (исходный план 0.x)

### Фаза 0. Каркас
Структура репозитория, лицензии, план, тестовые данные.

### Фаза 1. Индекс и сводки
- Определение корня выгрузки и версии формата (`MetaDataObject@version`).
- Индекс в SQLite (стандартная библиотека): объекты, реквизиты, табличные части, формы, команды, макеты, движения документов, роли и права, подписки, регламентные задания, функциональные опции, подсистемы.
- Обратные ссылки по типам реквизитов, составу подсистем, правам ролей, источникам подписок, обращениям из модулей.
- Команды: `build`, `info <объект>`, `refs <объект>`, `find <подстрока>`.
- Критерии: индекс выгрузки БСП (2248 модулей, 909 форм) строится за приемлемое время и без чтения всего XML в память; повторная сборка инкрементальная.
- **Статус: выполнено (v0.1).** Результаты: БСП 3.1 (формат 2.20, 2701 объект, 1,17 млн строк BSL) - первая сборка 5-10 с, повторная без изменений 0 с, правка одного модуля 0,1 с. Ссылки из кода сверены с grep по 2 объектам: расхождения только комментарии (индекс их пропускает) и форма `Метаданные.Справочники.X` (индекс её учитывает). Проверено на форматах 2.11 (старая самописная база) и 2.20. Модули обычных форм читаются из `Form.bin`.
- Реализовано: `build`, `stats`, `info`, `refs`, `find`; навыки `onec-explore`, `onec-xrefs`; контейнер `Form.bin` (`v8container.py`: чтение, запись без сжатия, проверка круговой сборкой).
- Не проверено: работа на полной выгрузке ERP-класса (ожидается 2-4 минуты на первую сборку), загрузка собранного `Form.bin` в платформу, подстановка `${CLAUDE_PLUGIN_ROOT}` и шаблонов `allowed-tools` в установленном плагине.

### Фаза 2. Запросы
- Извлечение текстов запросов из строковых литералов модулей, из наборов данных СКД и из форм.
- Разбор таблиц, полей, виртуальных таблиц и параметров, привязка к индексу.
- Типовые замечания по стандартам запросов.

### Фаза 3. Стандарты офлайн
- `sync_standards.py` загружает снимок стандартов и соответствий диагностик (источник: открытый проект v8std).
- Локальный индекс: номер, название, пункты, связанные коды АПК, BSL LS, v8-code-style.
- Тексты стандартов кладутся в `standards/` публичного репозитория (решение владельца проекта) с заголовком: источник, дата снимка, правообладатель (© фирма «1С»). В `standards/README.md` указано, что тексты удаляются по требованию правообладателя.
- Собственные материалы (индекс, соответствие диагностик, чек-листы) лежат отдельно от дословных текстов.

### Фаза 4. Формы
- Управляемые: дерево элементов, реквизиты, команды, события и связь с обработчиками модуля.
- Обычные: разбор контейнера `Form.bin`, извлечение модуля, структурный дамп раскладки. Имена элементов не придумываются там, где формат их не содержит.
- Записи `Form.bin` никогда не сжимаются.
- Для этой фазы нужны образцы реальных обычных форм.

### Фаза 5. Безопасная правка
- Резервная копия, режим `--dry-run`, проверка структуры, версия формата по платформе выгрузки.
- Метаданные: реквизиты, табличные части, формы, команды. Формы: элементы, реквизиты, команды.
- Загрузка в информационную базу проверяется человеком на машине с платформой.

### Фаза 6. Оформление и проверка
- Оценки срабатывания описаний, проверка стоимости в контексте (`/skill-doctor`).
- Упаковка для установки: локально и через `/plugin marketplace add`.
- README, примеры, публикация.

## Тестовые данные

- Публичная выгрузка БСП (формат 2.20) — крупный образец, загружается скриптом.
- Фикстуры из MIT-проектов для краевых случаев.
- Образцы реальных конфигураций (включая обычные формы) — только локально, в репозиторий не попадают.

## Известные ограничения

- В среде разработки нет платформы 1С, поэтому проверка загрузки правок в базу делается вручную.
- Формат выгрузки меняется между версиями платформы; поддерживаются 8.3.27 и 8.5, остальные версии считаются нецелевыми.
- Обычные формы читаются структурно; полная семантика раскладки требует проверки на реальных образцах.
